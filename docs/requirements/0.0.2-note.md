# 0.0.2 —— 收口笔记

> **版本状态**：✅ 已确定
> **表结构变更**：需新表 `sgj_note_draft`（FR-002-7 草稿箱）
> **设计方案**：[笔记收口（0.0.2）设计](../design/note-0.0.2-design.md)
> **决策**：D-1 ~ D-4 已全部拍板，见文末

## 1. 最终目标

**笔记从「能写」变成「写不丢、找得回」，本版可发布。**

## 2. 范围

前台笔记模块的列表、编辑、详情三页，新增**草稿箱页**；后台笔记管理页同步支持正文检索。不涉及条目模块。

### 3.2 需求说明

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-002-1 | 笔记正文可检索 | 列表检索由「仅标题」扩展为「标题 + 正文」，由新增的 `keyword` 参数承载（`title` 保留「仅标题」原义，后台表单仍用它）。SQL 采用 `(title like or content like)`，**括号是安全边界**，漏写会让匿名访客搜到私密与回收站笔记，见[设计 §2.3](../design/note-0.0.2-design.md)；FULLTEXT + ngram 留待笔记量上来后替换，接口形状不变。回收站不纳入 |
| FR-002-2 | 命中片段展示 | 前台列表**不再下发正文**，改下发服务端生成的纯文本摘要（`excerpt`）并**常显**：无关键词取正文开头，有关键词取命中窗口且以命中处为中心。前端按关键词切片段渲染高亮，不拼 HTML、不走 `v-html`。后台列表与导出仍带 `content`；摘要剥离规则见[设计 §3.3](../design/note-0.0.2-design.md) |
| FR-002-3 | 编辑草稿自动保存 | 打字时先写 `localStorage`（停手 1s，保证断网 / 强杀不丢），每 15s 与页面离开时推服务端。进编辑器时比对本地 `savedAt` 与服务端 `updateTime` 取较新者；编辑已有笔记的保存草稿**静默恢复**并显示页内状态条（不弹提示、不进草稿箱）。保存成功即同事务删除草稿 |
| FR-002-4 | 未保存离开确认 | 判据为「与打开时的服务器快照不同」（不能用「与草稿是否相同」，草稿总是最新的）；路由离开、取消按钮、浏览器后退、关闭标签页均拦截；确认离开后**保留**草稿。移动端关闭页面不承诺弹窗，见 §5 |
| FR-002-5 | 代码块语法高亮 | Markdown 的 fenced code 块按语言高亮。新增 `highlight.js` + `marked-highlight` 两个依赖（`marked` 12 已**彻底移除**内置 `highlight` 选项）；只高亮显式标注且认识的语言，不启用自动猜语言 |
| FR-002-6 | 前台全局搜索入口 | ↪ **移出本版**，转 0.0.5。原方案设想的「接上闲置 `HeaderSearch` 组件」不成立：该组件被后台侧栏引用，是 Fuse.js 的菜单搜索、零后端调用，前台亦无搜索位 |
| FR-002-7 | 服务端草稿箱 | 新表 `sgj_note_draft`（**独立表**，不给 `sgj_note` 加标志位：后者要求六处既有查询永远记得排除草稿，漏一处即草稿静默进入列表 / 统计 / 导出）。**只本人可见**（不走 `resolveCreateBy()` 的管理员旁路），接口不加 `@Anonymous`；草稿箱只装新笔记草稿（`note_id` 为空），编辑态草稿不入箱；删除为硬删除、不进回收站；上限 20 份、不做自动过期；入口为列表页入口条 + 独立页 `/note/draft` |

**对应 issue**：#30（FR-002-1）、#31（FR-002-2）、#32（FR-002-3）、#33（FR-002-4）、#34（FR-002-5）、#35（FR-002-7，已拆子 issue #37 建表与草稿接口、#38 保存笔记时一并删掉草稿、#39 草稿箱页面与入口）。FR-002-6 已移出本版，未建 issue。以上均挂 milestone「0.0.2」；依赖关系：#31 ← #30、#32 ← #37、#33 ← #32、#39 ← #37 与 #32。

## 4. 非目标

- 不做笔记版本历史、笔记分类 / 文件夹（标签体系已覆盖，加层级分类属概念通胀）；
- 不做笔记导入 / 导出（Issue #14 由他人负责，待其合入后再评估是否需要补漏）；
- 不做全文索引调优（个人规模笔记量下 LIKE 足够）；
- 不做「想法」等新的记录类型（详见[需求文档索引](README.md)的「跨版本约束与原则」）；
- 不做草稿的自动过期清理任务；不做后台草稿页面。

## 5. 验收标准

完整清单见[笔记收口设计 §8](../design/note-0.0.2-design.md)，此处只列对原稿有修正的关键项：

**检索与摘要**

- [ ] 搜索一个只存在于正文、标题中不含的词，能命中该笔记；命中摘要**常显**、以命中处为中心且关键词高亮；
- [ ] 匿名带 `keyword` 请求搜博主私密笔记正文 → **0 命中**（`or` 未加括号会短路 `create_by` / `is_public` 过滤，已固化为回归用例）；
- [ ] 后台笔记管理页用同一关键词可搜到正文命中项，label 显示「关键词」；回收站仍只搜标题。

**草稿与草稿箱**

- [ ] 新增笔记写一半离开 → 草稿出现在草稿箱，从草稿箱「继续写」能接着写且关联条目与离开前一致；编辑已有笔记写一半离开 → **不出现**在草稿箱，再次进入该篇静默恢复并显示状态条；
- [ ] 跨设备（≤15s）与断网续写：甲设备写一半乙设备可见并继续，断网期间内容由本地缓冲承接、恢复网络后同步到服务端；
- [ ] 草稿隔离：匿名请求草稿接口返回 401，甲用户看不到乙用户草稿，按他人 `draftId` 更新 / 删除 / 发布均被拒；
- [ ] 保存笔记后草稿行消失（同事务），草稿箱删除为硬删除、不进回收站；达到 20 份上限时新建被拒并提示清理；
- [ ] 首页 `noteTotal` 与「最近笔记」不受草稿影响。

**离开确认**

- [ ] 有未保存改动时「取消 / 返回 / 后退 / 关闭标签页」均有确认，保存成功后的跳转不弹确认。**桌面端**要求关闭标签页弹确认；**移动端**不要求关闭页面弹确认，改为要求草稿可恢复（iOS 的 `beforeunload` 不可靠）；
- [ ] 确认离开后草稿仍在。

**高亮**

- [ ] 笔记正文中的代码块有语法高亮，且渲染结果未被消毒误伤；
- [ ] 无语言标注与未知语言的代码块原样显示，不报错；详情页与编辑页实时预览均生效。

**不可回归**

- [ ] 标签筛选、条目筛选（`itemId`）、分页、公开性过滤（匿名仅见 `is_public='1'`）、回收站恢复与彻底删除流程，以及后台导出的「内容」列均无回归。

## 6. 数据与兼容性

- **表结构变更：需新表 `sgj_note_draft`**（FR-002-7 草稿箱），增量脚本 `sql/update/20260917_note_draft.sql`，并同步 `init_business.sql` 供新库使用；草稿表无存量数据，无需回填或迁移。
- 除上表外无其他表结构变更（FR-002-1 采用 LIKE 方案；`keyword` / `excerpt` / `draftId` 是域对象的非表字段，与既有的 `itemName` 同类）。
- 草稿用**独立表**而非给 `sgj_note` 加标志位：标志位方案要求六处既有查询（列表 / 详情 / 回收站 + Dashboard 的四处统计与最近笔记）永远记得排除草稿，漏一处不报错、只静默泄露，且无单一收敛点可加保险。理由与字段设计见[设计 §4.1](../design/note-0.0.2-design.md)。
- FR-002-5 需新增**两个**前端依赖：`highlight.js` + `marked-highlight`。理由：`marked` 12 已彻底移除 `highlight` 选项，语法高亮亦无标准库可用；`marked-highlight` 是 marked 官方组织维护的插件，用它可省掉自写渲染器胶水。
- 高亮通过 `MarkdownViewer` 的既有 `DOMPurify.sanitize` 管道输出，需验证 `hljs` 生成的 `span class` 未被过滤（`class` 默认在 DOMPurify 白名单内，已列为 `MarkdownViewer` spec 的断言）。
- 前台列表不再下发 `content` 后，`MarkdownViewer` 不再被列表页引用，高亮库只落在详情 / 编辑 / 后台三个懒加载路由，首屏不付这份体积。

## 7. 已拍板的决策

| 编号 | 问题 | 结论 |
| --- | --- | --- |
| D-1 | 检索范围是否需要区分「仅标题 / 仅正文 / 全部」？ | 合并为「全部」，不增加筛选维度。新增 `keyword` 参数承载，`title` 保留「仅标题」原义 |
| D-2 | 命中片段由后端返回还是前端计算？ | **后端**，并让前台列表不再下发 `content`、改下发 `excerpt`。（原理由「避免前端把整篇正文拉到列表接口」不成立——列表本来就在返回全文） |
| D-3 | 草稿的保留时长与上限？多设备是否需要同步？ | **服务端草稿箱**（立 FR-002-7，新表 `sgj_note_draft`）：本地 1s 缓冲 + 服务端 15s / 离开时同步，进编辑器取时间戳较新者；草稿箱只装新笔记草稿、上限 20 份、不做自动过期；保存成功同事务删除草稿。原结论「本地保留最近 1 条、不清除」被推翻——既不跨设备，且不清除会导致刚保存完又被问是否恢复（点恢复等于回退版本） |
| D-4 | **范围类** FR-002-6 全局搜索是否纳入 0.0.2？ | **不纳入**，转 0.0.5。（原建议「`HeaderSearch` 已是现成组件」不成立：它被后台侧栏引用、是菜单搜索，且前台没有搜索位） |
