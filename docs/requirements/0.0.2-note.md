### 3.2 需求说明

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-002-1 | 笔记正文可检索 | 列表检索由「仅标题」扩展为「标题 + 正文」，由新增的 `keyword` 参数承载（`title` 保留「仅标题」原义，后台表单仍用它）。实现为 **MySQL FULLTEXT + ngram**：一条复合索引同时覆盖标题与正文，查询 `match(title, content) against(#{keyword} in boolean mode)`——不需要 `or`，因而没有越权短路风险。用**布尔模式**是实测结论：自然语言模式会把 `mysql` 命中到只含 `sql` 的笔记。回收站不纳入。约束见 §3.3（单字搜不到、布尔运算符） |
| FR-002-2 | 命中片段展示 | 前台列表**不再下发正文**，改下发服务端生成的纯文本摘要（`excerpt`）并**常显**：无关键词取正文开头，有关键词取命中窗口且以命中处为中心。前端按关键词切片段渲染高亮，不拼 HTML、不走 `v-html`。后台列表与导出仍带 `content`；摘要剥离规则见[设计 §2.6](../design/note-0.0.2-design.md) |
| FR-002-3 | 编辑草稿自动保存 | 打字时先写 `localStorage`（停手 1s，保证断网 / 强杀不丢），每 15s 与页面离开时推服务端。进编辑器时比对本地 `savedAt` 与服务端 `updateTime` 取较新者；编辑已有笔记的保存草稿**静默恢复**并显示页内状态条（不弹提示、不进草稿箱）。保存成功即同事务删除草稿 |
| FR-002-4 | 未保存离开确认 | 判据为「与打开时的服务器快照不同」（不能用「与草稿是否相同」，草稿总是最新的）；路由离开、取消按钮、浏览器后退、关闭标签页均拦截；确认离开后**保留**草稿。移动端关闭页面不承诺弹窗，见 §3.3 |
| FR-002-5 | 代码块语法高亮 | Markdown 的 fenced code 块按语言高亮。新增 `highlight.js` + `marked-highlight` 两个依赖（`marked` 12 已**彻底移除**内置 `highlight` 选项）；只高亮显式标注且认识的语言，不启用自动猜语言 |
| FR-002-6 | 前台全局搜索入口 | ↪ **移出本版**，转 0.0.5。注意 `HeaderSearch` 不能直接复用：它被后台侧栏引用，是 Fuse.js 的菜单搜索、零后端调用，而且前台没有搜索位 |
| FR-002-7 | 服务端草稿箱 | 新表 `sgj_note_draft`（**独立表**，不给 `sgj_note` 加标志位：后者要求六处既有查询永远记得排除草稿，漏一处即草稿静默进入列表 / 统计 / 导出）。**只本人可见**（不走 `resolveCreateBy()` 的管理员旁路），接口不加 `@Anonymous`；草稿箱只装新笔记草稿（`note_id` 为空），编辑态草稿不入箱；删除为硬删除、不进回收站；不设数量上限、不做自动过期；入口为列表页入口条 + 独立页 `/note/draft` |

### 3.3 详细需求分析

逐个需求给出**场景**、**期望行为**与**边界与异常**。边界表是验收与测试用例的来源；每条边界对应的技术实现选择见[设计 §2](../design/note-0.0.2-design.md)的结论清单（结论编号如下称「设计 结论 N」）。

#### FR-002-1 笔记正文可检索

**场景**：只记得正文里的某个说法，不记得标题里有没有。现在这种情况搜不到。

**期望行为**：列表页搜索框从「仅标题」扩展为「标题 + 正文」。后台笔记管理页共用同一关键词参数，label 由「标题」改为「关键词」。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | **匿名越权短路（安全）** | 匿名带 `keyword` 必须**只能**搜到公开且未删除的笔记，0 条也不得泄露存在性。这条是硬边界，已固化为回归用例（设计 §2.3） |
| 2 | 回收站不纳入 | 回收站仍只按标题检索（表格无内容列，命中理由不可见） |
| 3 | 布尔模式的运算符 | `+` `-` `*` `"` 等会被当作运算符解释；**前导 `-` 会让结果返回 0 行**，而包引号屏蔽不掉（ngram 会把符号丢掉）。实现须在传参前剔除这些字符（[设计 §2.3](../design/note-0.0.2-design.md)） |
| 4 | 大小写 | 检索不区分大小写；前端高亮必须同样不敏感，否则出现「搜得到却不高亮」 |
| 5 | 只输入空白 | 视为未输入关键词，不参与过滤 |
| 6 | 与标签 / 条目筛选共存 | `keyword`、`tags`、`itemId` 可叠加，结果是三者同时满足 |
| 7 | 命中在正文、标题不含 | 必须命中（本需求的核心价值） |
| 8 | 搜索框清空 | 恢复全量列表 |
| 9 | 单个汉字 / 单个字符 | **搜不到**——`ngram_token_size=2` 的硬约束（实测）。搜索框需最小长度约束与提示（「请至少输入 2 个字」） |
| 10 | 英文单词的精确性 | 必须用布尔模式：自然语言模式会把 `mysql` 命中到只含 `sql` 的笔记（实测） |

#### FR-002-2 命中片段展示

**场景 A（浏览）**：进列表页不看搜索，也要能一眼看出每篇写了什么。
**场景 B（检索）**：搜到一个只存在于正文的词，卡片要让我看见它在哪句话里。

**期望行为**：前台列表不再下发正文，改为服务端生成的纯文本摘要 `excerpt` 并常显。无关键词取正文开头，有关键词取命中窗口且以命中处为中心；前端按关键词切片段渲染高亮。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | 摘要与卡片标题重复 | 正文以与标题同名的一级标题开头时，摘要里**只出现一次**（承接原前端 `previewContent()` 的职责，设计 结论 20） |
| 2 | 命中落在代码块里 | 纯文本摘要不含代码块内容，无法居中显示命中处 → 摘要取正文开头，不因命中而空白 |
| 3 | 整篇只有代码块 | 回退为原始文本开头，卡片不得空白 |
| 4 | 正文为空 | 不渲染预览区 |
| 5 | 关键词含正则元字符 | 关键词含 `(` `[` `*` 等时，高亮**不得报错**（按字面量切分） |
| 6 | 底部渐隐压在完整文字上 | 摘要是定长的，而现有底部渐隐是为「预览整篇、必然溢出」设计的，改后会压在完整文字上，看起来像被截断 → 渐隐改为**仅在内容溢出时**显示（设计 结论 20 同批） |
| 7 | 只命中标题 | 摘要取正文开头，标题单独高亮 |
| 8 | 后台与导出不受影响 | 后台列表摘要列、CSV / JSON 导出的「内容」列仍须有值 |
| 9 | 条目详情的关联笔记列表 | 同源改造，同样吃摘要、同样高亮 |

#### FR-002-3 编辑草稿自动保存

**场景 A（换设备）**：在手机上写了一半，回家打开电脑要能接着写。
**场景 B（编辑已有笔记）**：改一篇已发布的笔记改了一半关掉，回来要能接着改。
**场景 C（意外关闭）**：写一半误关标签页 / 浏览器崩溃 / 断网。

**期望行为**：打字时先写本地（停手 1s），每 15s 与页面离开时推服务端；进编辑器时取本地与服务端中较新的一份；编辑已有笔记的草稿静默恢复并显示状态条；保存成功即同事务删除草稿。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | **同一浏览器换用户** | 后一个登录的用户**看不到**前一个用户的未保存内容（本地缓冲必须按用户隔离，设计 结论 26） |
| 2 | 断网时的自动保存 | 断网期间不得连续弹错误提示（后台同步静默）；内容由本地缓冲承接，恢复网络后自动同步到服务端（设计 结论 22） |
| 3 | 网络恢复 | 恢复后**立即**重推一次，不等下一个 15s 周期 |
| 4 | 同一浏览器内短间隔重复保存 | 不得被「重复提交」保护误拦（设计 结论 22） |
| 5 | 多设备同时编辑同一篇 | **接受后写覆盖**：后推送的一方覆盖另一方，作为已知上限（设计 结论 24） |
| 6 | 时间戳可比性 | 本地时间与服务端时间必须能正确比较，不得因格式差异把新旧判断反（设计 结论 27） |
| 7 | 空表单 | 新建笔记时标题与正文都为空则**不创建草稿**，避免草稿箱里全是空草稿 |
| 8 | 两台设备都离线进入同一篇 | 不得产生两条指向同一笔记的草稿行（服务端按 用户 + 笔记 定位既有草稿） |
| 9 | 草稿数量 | **不设数量上限**（设计 结论 14）；草稿的出口只有「手动删」「保存成功后删」「笔记被删时一并删」，不做自动过期清理 |
| 10 | 他人草稿 | 按他人 `draftId` 更新 / 删除 / 发布一律被拒 |
| 11 | 「放弃草稿」 | 删草稿之外还须**把表单回滚到服务器快照**，否则用户以为内容还在，且点取消时仍会被拦 |
| 12 | 关联条目 | 「继续写」时关联条目与离开前一致（草稿须存 `item_id`） |
| 13 | 标签已被后台删除 | 草稿里的标签回填时容错，不报错、不静默丢值 |
| 14 | 页面离开时的推送 | 不保证送达（页面卸载会取消请求）→ 须先同步写本地缓冲，未送达由「下次进编辑器时本地较新则补推」兜底 |
| 15 | 无标题草稿 | 草稿可以没有标题；草稿箱展示时用正文首行兜底 |
| 16 | 状态可见性 | 编辑页须显示同步三态：已同步到草稿箱 / 仅本地待同步 / 已恢复未保存的草稿（设计 结论 23） |

#### FR-002-4 未保存离开确认

**场景**：写了一半点「取消」、点返回、点浏览器后退、直接关标签页。

**期望行为**：有未保存改动时四个出口都拦；判据是「与打开时的服务器快照不同」；确认离开后草稿保留。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | 判据不能用「与草稿是否相同」 | 草稿总是最新的，那样写等于永不拦截 |
| 2 | 新增态的改动判据 | 标题或正文非空，或关联条目 / 标签 / 公开状态偏离初始值 |
| 3 | 保存成功后 | **不得**弹确认（保存后的跳转要放行） |
| 4 | 恢复草稿后 | **算**已改动（内容确实不同于已发布版本）；取消时文案须说明「已保存到草稿箱」而非「修改将丢失」 |
| 5 | 点过「放弃草稿」 | 表单已回滚到快照，再点取消不再弹确认 |
| 6 | 关闭标签页的文案 | 浏览器原生确认框文案不可自定义，不得承诺能写入「已保存到草稿箱」（设计 结论 30） |
| 7 | 桌面端 | 关闭标签页须弹浏览器原生确认 |
| 8 | 移动端 | **不要求**关闭页面弹确认（iOS Safari 的 `beforeunload` 不可靠），改为要求「重新进入时草稿可恢复」 |
| 9 | 保存中 / 校验失败 | 不弹确认 |

#### FR-002-5 代码块语法高亮

**场景**：笔记里的 Java / SQL / JSON 代码块现在是一整块同色文字，读起来费劲。

**期望行为**：Markdown 的 fenced code 块按语言高亮；详情页与编辑页实时预览共用同一渲染组件，自动同时生效。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | 无语言标注 | 原样显示，不报错、不高亮 |
| 2 | 不认识的语言 | 原样显示，不报错 |
| 3 | 不猜语言 | 不启用自动识别（长代码块明显变慢且易猜错） |
| 4 | 消毒不得误伤 | 高亮输出必须通过既有的消毒管道，且高亮标记不能被过滤掉 |
| 5 | 深浅两种主题 | 代码块在两种主题下都保持深色（与现状一致），配色须协调 |
| 6 | 列表页体积 | 前台列表改为纯文本摘要后不再引入 Markdown 渲染器，首屏不得因此变大 |
| 7 | 编辑页实时预览 | 与详情页同样生效 |
| 8 | 与大纲导航共存 | 详情页既有的大纲锚点不受影响 |

#### FR-002-7 服务端草稿箱

**场景 A**：新增笔记写一半离开 → 草稿出现在草稿箱，回来点「继续写」接着写。
**场景 B**：编辑已有笔记写一半离开 → **不出现**在草稿箱，再次进入该篇静默恢复。

**期望行为**：新表 `sgj_note_draft`（独立表），只本人可见，只装新笔记草稿，硬删除，不设数量上限，入口为列表页入口条 + 独立页 `/note/draft`。

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | 匿名访问 | 草稿接口返回 **401**，不是 200 空列表（草稿是未完成的私密文字） |
| 2 | 管理员 | 管理员**不可**读他人草稿（不沿用 `resolveCreateBy()` 的旁路） |
| 3 | 匿名 / 过期 token 进列表页 | 不得弹出「登录状态已过期」确认框，也不得弹错误提示；未登录时不发草稿请求（设计 结论 21） |
| 4 | 入口条显示时机 | 仅登录且有草稿时显示，并显示草稿份数 |
| 5 | 编辑态草稿 | 不进箱；不设数量上限，但笔记被删除时一并清理（设计 结论 25） |
| 6 | 删除 | 硬删除，不进回收站 |
| 7 | 过期清理 | **不做**（无定时任务，清理交给用户） |
| 8 | 后台 | 不做草稿页面 |
| 9 | 相对时间 | 草稿箱显示「3 分钟前」这类相对时间，不得出现 `NaN` |
| 10 | 移动端 | 底部标签栏不得遮挡草稿箱内容 |
| 11 | 未登录直接访问 `/note/draft` | 跳登录页 |
| 12 | 草稿箱为空 | 列表页入口条不显示；直接访问草稿箱页显示空态 |

#### FR-002-8 笔记文件导入 / 导出（Issue #14，**本版仅 md**）

> **范围**：本版**只做 md**。Word（docx）解析转后续版本（见 §4）——docx 要新增解析依赖，还要做结构与内嵌图片转存，验收和 md 完全独立，适合单独排期。
>
> **拆分**：[#40 导入链路](https://github.com/MosaicAccount/shiguangji/issues/40)（解析 → 跳编辑页预填 → 保存时上传原件）与 [#41 导出与两个下载入口](https://github.com/MosaicAccount/shiguangji/issues/41)；两者都依赖 [#42 正文上限提升与列表瘦身](https://github.com/MosaicAccount/shiguangji/issues/42)。

**场景 A（导入）**：在电脑上用自己习惯的 markdown 软件写好笔记，传到站点上继续用（手机上接着改）。
**场景 B（往返）**：导出某篇笔记到本地改，改完再传回去，不要变成两篇。

**期望行为**

- 导入 md：前端本地读取文件 → 解析（剥离 YAML front-matter）→ **跳转到编辑页并预填**（标题、正文、表内的标签）→ 用户补完关联条目与公开状态后保存，成为一篇**常规笔记**；
- **点保存时才上传原件**，路径记在笔记的 `source_file` 上；上传失败只放弃留存，不阻断保存；
- 后台笔记管理页每行两个动作：**「下载原件」**（取回当初上传的那份）与**「导出 Markdown」**（用当前正文现生成，带 front-matter 含 `noteId`）；
- 重新导入带 `noteId` 的文件时，询问「更新《X》/ 新建一篇」；
- 前台不做下载 / 导出入口。

选「跳编辑页确认」而不是「上传即入库」的理由：不新增预览界面；标题 / 标签 / 关联条目 / 公开状态在保存前都能设（这正是「纳入系统管理」的动作）；解析失败或产物有问题时不会在库里留下垃圾笔记；而且导入的内容会走编辑页自己的草稿机制——导入后没保存就离开，草稿箱会兜住它。

**「纳入系统的管理」——导入后必须与手写笔记无差别**

| 管理能力 | 要求 |
| --- | --- |
| 出现在列表 | 与手写笔记无差别，受标签 / 条目 / 分页筛选 |
| 可检索 | 导入即进全文索引（写入时由 InnoDB 自动维护，无需额外动作） |
| 可编辑 | 进现有编辑页，分屏预览与草稿自动保存均生效 |
| 可删除 | 软删除进回收站、可恢复、可彻底删除 |
| 计入统计 | 首页 `noteTotal` 与「最近笔记」包含它 |
| 可打标签 / 关联条目 | 受标签管理约束，能挂到条目上 |
| 公开性 | 默认私密，可改公开 |

**边界与异常**

| # | 边界 | 要求 |
| --- | --- | --- |
| 1 | 标题必填 | `sgj_note.title` 是 `not null`（`init_business.sql:138`），导入必须能产出标题。取值顺序：front-matter 的 `title` → 正文首个 H1 → 文件名去扩展名 |
| 2 | front-matter 必须剥离 | md 文件普遍带 YAML front-matter（Obsidian / Jekyll / Hugo 都写）。留在正文里会让摘要首行显示成 `---`，并让 `title:` / `tags:` 这些键进 ngram 索引变成垃圾 token |
| 3 | 图片引用无法转存 | 相对路径 `![](./img/a.png)` 与 Obsidian 的 `![[a.png]]` 指向的文件，系统拿不到，必须**提示**而不静默丢失；`data:` base64 内嵌图片本版不处理 |
| 4 | Obsidian 方言 | `[[标题]]` 与 0.0.5 的双链语法（FR-005-1）是同一套，两边对齐；`![[图片]]` 明确不支持并提示 |
| 5 | 往返冲突 | 重新导入时若该笔记在网页端也被改过（服务端 `update_time` 晚于 front-matter 中记录的时间），须提示：覆盖 / 另存为新笔记 |
| 6 | 文件校验与超时 | 只接受 `.md`；限制体积（建议 5MB）；全局 `request.ts:20` 的超时是 10 秒，上传接口需单独放宽；非 md 与超大文件给出可读错误而不是 500 |
| 7 | 未登录 | 导入与导出均需登录，不得匿名 |
| 8 | 原件留存与回收 | 原件在**保存时**上传并**登记为「被引用」**，否则会被每周的孤儿文件清理任务误删；保存失败或用户放弃时原件由清理任务回收；笔记彻底删除后原件自动回收（设计 结论 37） |
| 9 | 上传原件失败 | **不阻断保存**——内容优先，仅放弃留存；不得因此让用户丢掉刚写的正文 |
| 10 | 从草稿恢复后保存 | 导入后未保存就离开、事后从草稿恢复再保存时**没有原件**（`File` 对象已随页面消失），`source_file` 为空即可，不算错误 |
| 11 | 「下载原件」不能用于往返 | 原件不含 `noteId`、也不含之后在网页上的修改，拿它重新导入会新建一篇重复笔记 → UI 文案须写明：往返请用「导出 Markdown」（设计 结论 39） |
| 12 | 标签对接 | front-matter 的 tags 只预填标签表中存在的；不在表里的忽略并提示「N 个标签不在标签表中，已忽略」，**不自动建标签**（设计 结论 38） |
| 13 | 解析失败 | 不得留下半成品笔记——走「跳编辑页、用户点保存才入库」，失败时给错误提示即可 |
| 14 | 导出时的图片链接 | 保持站点 URL 不变、不打包图片；往返编辑时链接不受影响 |
| 15 | 存储形态 | **正文仍存数据库**（设计 结论 31）；文件只是导入源与导出产物，不改变权威副本 |

## 4. 非目标

- 不做笔记版本历史、笔记分类 / 文件夹（标签体系已覆盖，加层级分类属概念通胀）；
- 不做全文索引的深度调优（分词器定制、相关度调参），**也不引入独立检索服务**（Elasticsearch / Meilisearch 之类）：检索用 MySQL 原生 FULLTEXT + ngram（FR-002-1）；
- 不做「想法」等新的记录类型（详见[需求文档索引](README.md)的「跨版本约束与原则」）；
- 不做草稿的自动过期清理任务；不做后台草稿页面；
- 不做跨设备并发冲突检测（接受后写覆盖，见 §3.3 FR-002-3 边界 5）；
- 不做批量导出 / 打包（导出只做单篇 .md，见 FR-002-8）；不做笔记目录整体导入（一次一个文件）；
- **本版导入只支持 md**：Word（docx）解析与内嵌图片转存转后续版本——它需要新增解析依赖、还要做结构与图片转存，验收与 md 独立，适合单独排期。

## 5. 验收标准

**检索与摘要**

- [ ] 搜索一个只存在于正文、标题中不含的词，能命中该笔记；命中摘要**常显**、以命中处为中心且关键词高亮；
- [ ] 摘要**不与卡片标题重复**——正文以同名一级标题开头时，摘要里只出现一次；
- [ ] 无关键词时卡片显示正文开头摘要，纯代码块笔记不出现空白卡片；
- [ ] 摘要卡片的底部渐隐只在内容真的溢出时出现，完整文字不被压暗；
- [ ] 关键词含 `(` `[` `*` 等字符时高亮不报错；
- [ ] 匿名带 `keyword` 请求搜博主私密笔记正文 → **0 命中**（`or` 未加括号会短路 `create_by` / `is_public` 过滤，已固化为回归用例）；
- [ ] 后台笔记管理页用同一关键词可搜到正文命中项，label 显示「关键词」；回收站仍只搜标题。
- [ ] 英文 `mysql` **不**命中只含 `sql` 的笔记（用布尔模式，非自然语言模式）；
- [ ] 只输一个汉字时有明确提示（ngram 最少 2 字），不出现「搜了却没反应」的空白；
- [ ] 关键词含 `-` / `+` / `*` 等符号时不报错、不产生空结果。

**草稿与草稿箱**

- [ ] 新增笔记写一半离开 → 草稿出现在草稿箱，从草稿箱「继续写」能接着写且关联条目与离开前一致；编辑已有笔记写一半离开 → **不出现**在草稿箱，再次进入该篇静默恢复并显示状态条；
- [ ] 跨设备（≤15s）与断网续写：甲设备写一半乙设备可见并继续，断网期间内容由本地缓冲承接、恢复网络后同步到服务端；
- [ ] 断网期间不连续弹错误提示；网络恢复后立即同步；
- [ ] 同一浏览器换用户登录，**看不到**上一个用户的未保存内容；
- [ ] 空表单（标题与正文都为空）离开后草稿箱不出现空草稿；
- [ ] 编辑页同步状态条三态正确：已同步到草稿箱 / 仅本地待同步 / 已恢复未保存的草稿；
- [ ] 草稿隔离：匿名请求草稿接口返回 401，甲用户看不到乙用户草稿，按他人 `draftId` 更新 / 删除 / 发布均被拒；
- [ ] 保存笔记后草稿行消失（同事务），草稿箱删除为硬删除、不进回收站；
- [ ] 首页 `noteTotal` 与「最近笔记」不受草稿影响。

**离开确认**

- [ ] 有未保存改动时「取消 / 返回 / 后退 / 关闭标签页」均有确认，保存成功后的跳转不弹确认。**桌面端**要求关闭标签页弹确认；**移动端**不要求关闭页面弹确认，改为要求草稿可恢复（iOS 的 `beforeunload` 不可靠）；
- [ ] 确认离开后草稿仍在；
- [ ] 点「放弃草稿」后表单回到服务器快照，再点取消不再弹确认。

**高亮**

- [ ] 笔记正文中的代码块有语法高亮，且渲染结果未被消毒误伤；
- [ ] 无语言标注与未知语言的代码块原样显示，不报错；详情页与编辑页实时预览均生效。

**导入 / 导出（FR-002-8，仅 md）**

- [ ] 上传 `.md` 后**跳到编辑页**且标题与正文已预填（标题按 front-matter → 首个 H1 → 文件名取值），补完标签 / 关联条目 / 公开状态后保存成功；
- [ ] 导入的笔记与手写笔记**无差别**：出现在列表、可被检索、可编辑、可删除进回收站、计入首页统计、可打标签挂条目；
- [ ] front-matter 已被剥离：卡片摘要首行不是 `---`，搜 `title` / `tags` 这类键不会命中它；
- [ ] front-matter 里不在标签表中的标签被忽略且有明确提示，不会静默写入词表；
- [ ] 后台笔记管理页的「导出 Markdown」导出带 front-matter（含 `noteId`）；改完重新导入时询问「更新《X》/ 新建一篇」，选更新**不产生重复笔记**；
- [ ] 后台的「下载原件」取回的是当初上传的那份；`source_file` 为空时该动作禁用；
- [ ] md 里的相对路径图片与 `![[图片]]` 有明确提示，而不是静默丢失；
- [ ] 非 md 文件、超大文件给出可读错误，不返回 500，也不留下半成品笔记；
- [ ] **上传的原件被登记为引用**（在 `selectReferencedStorageKeys()` 结果里），不会被每周的孤儿文件清理任务回收；上传原件失败时不阻断保存；
- [ ] 未登录不能导入或导出。

**不可回归**

- [ ] 标签筛选、条目筛选（`itemId`）、分页、公开性过滤（匿名仅见 `is_public='1'`）、回收站恢复与彻底删除流程，以及后台导出的「内容」列均无回归。

## 6. 数据与兼容性

- **表结构变更三处**：① 新表 `sgj_note_draft`（FR-002-7 草稿箱），增量脚本 `sql/update/20260917_note_draft.sql`；② `sgj_note` 新增全文索引 `ft_note_title_content (title, content) with parser ngram`（FR-002-1 改用 FULLTEXT + ngram），增量脚本 `sql/update/20260918_note_fulltext.sql`；③ `sgj_note` 新增 `source_file varchar(500) default ''`（FR-002-8 留存导入原件），增量脚本 `sql/update/20260918_note_source_file.sql`。三者均同步进 `init_business.sql` 供新库使用。草稿表与 `source_file` 无存量数据；全文索引会为已有行自动建立，**都不需要回填脚本**，但 `ADD FULLTEXT` 会锁表重建，量大时挑低峰执行。
- 除上述三处外无其他表结构变更：`keyword` / `excerpt` / `draftId` 是域对象的非表字段，与既有的 `itemName` 同类。
- 草稿用**独立表**而非给 `sgj_note` 加标志位：标志位方案要求六处既有查询（列表 / 详情 / 回收站 + Dashboard 的四处统计与最近笔记）永远记得排除草稿，漏一处不报错、只静默泄露，且无单一收敛点可加保险。理由与字段设计见[设计 §2.4](../design/note-0.0.2-design.md)。
- FR-002-5 需新增**两个**前端依赖：`highlight.js` + `marked-highlight`。理由：`marked` 12 已彻底移除 `highlight` 选项，语法高亮亦无标准库可用；`marked-highlight` 是 marked 官方组织维护的插件，用它可省掉自写渲染器胶水。
- 高亮通过 `MarkdownViewer` 的既有 `DOMPurify.sanitize` 管道输出，需验证 `hljs` 生成的 `span class` 未被过滤（`class` 默认在 DOMPurify 白名单内，已列为 `MarkdownViewer` spec 的断言）。
- 前台列表不再下发 `content` 后，`MarkdownViewer` 不再被列表页引用，高亮库只落在详情 / 编辑 / 后台三个懒加载路由，首屏不付这份体积。
- **新增一条全文索引**（不是新表）：`alter table sgj_note add fulltext key ft_note_title_content (title, content) with parser ngram;`——明细见本节第一、二条。
- `ngram_token_size` 是**只读启动变量**（默认 2，实测无法在线修改），生产环境须确认取值；一旦改动必须重建该索引，且查询语义随之变化（小于该长度的词搜不到）。
- **正文上限调整**：`SgjNoteServiceImpl.CONTENT_MAX_LENGTH` 由 20000 提到 100000（FR-002-8 的前置条件）。同时前台列表改为只取下正文的短文本，不再回传全文。
- FR-002-8 **本版不新增解析依赖**（只支持 md，按文本读取即可）；上传的原件走既有 `FileStorageService`，不新增存储形态。
- FR-002-8 的原件必须**登记为被引用**（给 `FileReferenceMapper.selectReferencedStorageKeys()` 加一行 union），否则会被每周的孤儿文件清理任务当成孤儿误删。这类缺陷不报错、只静默丢文件，已列为回归用例（见[设计 §2.11](../design/note-0.0.2-design.md)）。

## 7. 已拍板的决策

| 编号 | 问题 | 结论 |
| --- | --- | --- |
| D-1 | 检索范围是否需要区分「仅标题 / 仅正文 / 全部」？ | 合并为「全部」，不增加筛选维度。新增 `keyword` 参数承载，`title` 保留「仅标题」原义 |
| D-2 | 命中片段由后端返回还是前端计算？ | **后端**，并让前台列表不再下发 `content`、改下发 `excerpt`。（原理由「避免前端把整篇正文拉到列表接口」不成立——列表本来就在返回全文） |
| D-3 | 草稿的保留时长与上限？多设备是否需要同步？ | **服务端草稿箱**（立 FR-002-7，新表 `sgj_note_draft`）：本地 1s 缓冲 + 服务端 15s / 离开时同步，进编辑器取时间戳较新者；草稿箱只装新笔记草稿、不设数量上限（设计 结论 14）、不做自动过期；保存成功同事务删除草稿。只存本地不行：既不跨设备，且不清除会导致刚保存完又被问是否恢复（点恢复等于回退版本） |
| D-4 | **范围类** FR-002-6 全局搜索是否纳入 0.0.2？ | **不纳入**，转 0.0.5。（原建议「`HeaderSearch` 已是现成组件」不成立：它被后台侧栏引用、是菜单搜索，且前台没有搜索位） |

实现层面的决策记在[设计 §2.2](../design/note-0.0.2-design.md)的结论 20~39，包括：正文继续存数据库（文件只作导入源与导出产物）、正文上限提到 10 万字且列表改取短文本、检索改用 FULLTEXT + ngram、文件导入只做 md、原件留存与两个下载入口，以及摘要去重、草稿请求静默、同步三态、后写覆盖、本地缓冲按用户隔离、日期解析等实现细节。
