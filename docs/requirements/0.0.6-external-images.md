> **设计方案**：[external-images-design.md](../design/external-images-design.md)、[external-images-architecture.md](../design/external-images-architecture.md)、[external-images-testcases.md](../design/external-images-testcases.md)
> **决策**：D-32 ~ D-39 已拍板，见文末 §6

## 1. 背景与目标

0.0.2 的图片搬运（FR-002-9）只搬**本地文件**引用：用户指出文件在哪 → 上传 `/profile` → 改写引用。**外链**（`http(s):` / `//` 开头）只计数并明说「不参与搬运」（结论 62 / D-31）。原因是它的成本几乎全在安全面：服务器替用户访问任意网址就是 SSRF。

但外链是记录类产品的长期隐患，四类情况必然裂且无法事后补救：

1. **对方校验 Referer（防盗链）**：直接打开能看，嵌在自己页面里 403——最容易被误读成「搬运失败」；
2. **原图被删 / 图床关站 / 域名过期**：记录要放很多年，图没了通常几年后才发现，无从找回；
3. **对方限速或需要特殊网络**：显示慢或显示不出；
4. **`http://` 外链**：生产站点是 https 时按混合内容被浏览器拦掉（dev 是 http 看着正常，生产才炸）。

唯一能救的办法是**转存**：服务端把图下载一份到自己存储，正文引用改指 `/profile/...`。它买到四件事：不受对方删图 / 关站影响、不受防盗链约束、不受对方限速、http 变站内 https。

**最终目标**：导入带外链图片的笔记时，可以选择把外链逐张转存到自己服务器并改写引用；失败逐条可见且保留原引用；站点不因此变成开放代理。

## 2. 功能需求

| 编号 | 名称 | 描述 |
| --- | --- | --- |
| FR-006-1 | 外链图片转存 | 搬运弹窗（#56）里多一个可选项「顺带转存外链图片（N 处）」，**默认不勾**（转存是备份，不是搬运）。勾选后与本地图片搬运同一条进度管线：逐张调服务端抓取 → 落 `upload` 分类、uuid 命名、登记 `sys_file` → 正文引用改写为 `/profile/...`。协议相对地址 `//cdn/x.png` 按 `https:` 补全后转存 |
| FR-006-2 | 只有外链也要能进弹窗 | 正文只有外链（无本地引用）时，搬运弹窗同样打开：只显示外链转存选项与「转存外链图片」动作，不再因为没有本地文件可指而失去入口 |
| FR-006-3 | 转存结果逐条可见 | 成功 / 失败分开计数；**失败的逐条列出外链地址与原因**（超时、非图片、被拒、超体积），不静默。失败的引用保留原文，不丢用户内容 |
| FR-006-4 | 导入后补做 | 弹窗结果态里，未转存的外链（未勾选或部分失败）可通过「补转存外链」再跑一遍，复用同一条管线 |
| FR-006-5 | 安全面（本版的主要成本） | 服务器替用户访问任意网址，必须有完整的 SSRF 防护：只允许 `http(s)`；解析 IP 后拒绝回环 / 私网 / 链路本地 / 保留段；重定向每跳重新校验、限跳数；连接与读取超时、单张体积上限；登录必需 + 每用户速率限制。详见设计文档 §3.2 |
| FR-006-6 | 回收侧闭环 | 转存后的引用就是 `/profile/...`，直接落进 #56 的渲染与孤儿对账链路：被正文引用保活、删掉引用后被每周清理回收，不产生永不清理的垃圾 |

## 3. 边界

| # | 边界 |
| --- | --- |
| 1 | 转存只发生在用户显式勾选 / 点击时，**不做自动后台转存**（不扫库、不定期同步对方图床） |
| 2 | `data:` base64 内嵌图维持不处理（0.0.2 结论 35 后半段继续成立） |
| 3 | 已是 `/profile/` 的站内引用不算外链（导出再导入的往返不动它，结论 47） |
| 4 | 对方要 Referer 时服务端抓取同样会失败——如实展示失败原因即可，不伪造 Referer 绕过 |
| 5 | 后台条目封面 / 相册的外链不在本版范围（豆瓣封面已有白名单转存链路，issue #68 只承接笔记正文外链） |

## 4. 非目标

- 不做主机黑 / 白名单配置（外链来自全世界，白名单无意义；内网段拒绝已由 IP 校验覆盖，见 D-35）；
- 不做图片压缩、缩略图、格式转换、按内容哈希去重（沿 0.0.2 非目标）；
- 不做失败自动重试队列（失败逐条可见，用户自己决定补做）。

## 5. 验收清单

- [ ] 正文里的外链图片可勾选转存，转存后引用变成 `/profile/...`，详情页从本站出图；
- [ ] 只有外链的笔记也能打开搬运弹窗完成转存（FR-006-2）；
- [ ] 内网地址（`127.0.0.1`、`localhost`、`10.x`、`192.168.x` 等）、非 `http(s)` 协议一律被拒，并有可读错误；
- [ ] 重定向不越权（每跳重新校验）、限跳数；连接 / 读取超时与单张体积上限生效；
- [ ] 只落图片（Content-Type + 魔数双校验），非图片被拒且不落盘、不登记台账；
- [ ] 抓取失败逐条可见；失败时保留原引用，不丢用户内容；
- [ ] 转存后的图纳入孤儿对账：引用被删后能被回收；
- [ ] 站点不会变成开放代理：接口需登录，且有速率限制（每用户每分钟上限）。

## 6. 决策

| 编号 | 状态 | 议题 | 结论 |
| --- | --- | --- | --- |
| D-32 | 已拍板 | 转存入口 | 搬运弹窗内可选项（默认不勾）+ 结果态补做，不新增独立页面；只有外链时弹窗照开（FR-006-2） |
| D-33 | 已拍板 | 服务端形态 | 新端点 `POST /common/upload/fetch-image`（需登录）：入参 `{url}`，出参 `{path}`；抓取器做成 `ExternalImageFetcher` 接口，实现在 `web/service/image/` |
| D-34 | 已拍板 | SSRF 防护归属 | URL 校验 / DNS 解析后 IP 段拒绝 / 重定向逐跳重验 / 超时 / 体积上限都在**抓取器**内（接口契约的一部分）；Content-Type + 魔数的内容校验在**转存服务**内（落盘前最后一道，单点把关）。见设计 §3.2 |
| D-35 | 已拍板 | 不做主机黑 / 白名单 | 白名单与「外链来自全世界」矛盾；内网 / 保留段拒绝由 IP 校验完成，黑名单是它的弱化版 |
| D-36 | 已拍板 | 速率限制 | 每用户每分钟 30 次（Redis 分钟桶计数，可配），登录必需；张数上限沿用弹窗单次 50 张（前端），单张体积 10MB（服务端） |
| D-37 | 已拍板 | 失败可见性 | 每次调用一张、失败即回可读错误；前端逐条列出 URL + 原因；不做批量事务（部分成功部分失败是常态） |
| D-38 | 已拍板 | 存储与台账 | 复用 `FileStorageService.upload("upload", …, NOTE_IMAGE_EXTENSION, true)` + `sys_file` 台账 + 孤儿对账（与 #56 的笔记插图完全同一条链路） |
| D-39 | 已拍板 | 测试口径 | 抓取器的 SSRF 矩阵用本机地址做拒绝向量；成功路径 / 重定向链用 `allow-private-ranges` 测试开关在本地桩服务器验证（默认 false，设计 §3.4） |
