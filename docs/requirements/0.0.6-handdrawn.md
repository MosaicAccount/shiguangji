## 1. 最终目标

**前台视觉从「冷雾胶片」整体切换为手绘手账风格。这不是把样式刷匀，而是一次设计语言换代：拾光记本来就是一本「一个人的手账」，手绘（照片贴进去、胶带粘住、字写在格子里）才是日记本的语言。**

现状心愿页（`/plan`）已落地手绘清单视觉并获认可（#84，设计图 `docs/design/mockups/plan-0.0.3/handdrawn-checklist.html`），但它是全站唯一的例外页面，风格割裂被感知为「没做完」。解决不统一有两条路：退回去统一，或走过去统一——本版选择走过去（D-40）。

有利条件：手绘皮肤与站点令牌**同源**——`handdrawn.css` 的 `--hd-red:#A85F52` 即 `--sgj-primary`（灰陶红），`--hd-moss` 即 `--sgj-moss`，灰铜、暗色全套同 hex。色彩系统与状态语义已经统一，真正要换的只是**形制层**：字体、边框、形状、质感。这不是推倒重来，是同一套骨架换皮。

## 2. 范围

前台全部页面与共享组件的手绘化：

- **页面**：首页 / 影单 / 书单 / 足迹（含地图「裱框」，见 D-45）/ 笔记（列表 + 详情 + 编辑）/ 登录注册；心愿页已手绘，纳入统一令牌管理；
- **组件**：Element Plus 的弹窗、抽屉、日期选择、消息提示等（心愿页目前的做法是弹窗保持 EP 原样，全站统一时此边界不成立）；
- **字体**：自托管霞鹜文楷（OFL，结论 107）全站加载，核心片语料含全站文案（`scripts/gen-handdrawn-font.py` 可重跑）；全站生效则字体 CSS 不再随单页路由加载，需并入全局并复核核心片体积与首屏代价；
- **适配**：暗色模式与移动端随每页换装同步校准；
- **令牌**：`handdrawn.css` 从 `.plan-page` 作用域升格为全站令牌（色彩层继承 `sgj-*`，形制层 `hd-*` 转正）。

## 4. 非目标

- 不改任何后端接口、表结构、业务逻辑——本版只换视觉，不新增功能；
- 足迹地图瓦片不做手绘化（手账里贴一张真地图本来就是常态）；
- 不引入新字体、新 UI 框架。

## 5. 验收标准

- [ ] 前台所有页面（含登录注册）视觉统一：字体、边框、配色、空态同属手绘语言，无「例外页面」；
- [ ] 心愿页纳入全站令牌后视觉无回归；
- [ ] 表单录入效率不明显劣化：弹窗、日期选择、下拉的可用性保持；
- [ ] 笔记详情长文排版通过专项评审；
- [ ] 字体核心片体积与首屏代价复核通过（有量化结论）；
- [ ] 暗色模式全页校准，无「亮色手绘、暗色EP」的混搭；
- [ ] 回归：既有功能（增删改查、筛选、地图、笔记读写、主题切换、移动端）无回归。

## 6. 数据与兼容性

无表结构变更、无接口变更。约束：视觉切换不得改变 DOM 语义与可访问性——标题层级、focus 顺序、对比度维持既有标准。

## 7. 实施策略（建议，随设计评审定稿）

**按页灰度，高风险先行**（D-42）：

1. 设计语言文档 + 共享手绘组件（FR-007-1，地基）；
2. 影单网格页、笔记详情页两页高风险原型先行——密度页扫读与长文阅读是手绘最可能闯不过的两关，先验证再铺开；
3. 导航外壳 + 首页 → 影单 / 书单 → 足迹 → 笔记排版，逐页换装；
4. 每页沿用 #84 的「设计图先行、确认后落地」流程，任何一步停下都是一个完整可发布状态。

若第 2 步原型闯不过评审，退回「双风格有边界共存」并把边界做实（导航、文案、转场上的暗示性设计），该退路随设计评审一并确认。
