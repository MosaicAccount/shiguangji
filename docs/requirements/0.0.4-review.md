# 0.0.4 —— 回顾

> **版本状态**：✅ 已确定（详细需求已定稿，D-11 ~ D-13、D-47 ~ D-49 已拍板，见 §8）
> **表结构变更**：无（全部基于现有数据聚合）
> **设计方案**：已产出（`docs/design/review-architecture.md` / `review-design.md` / `review-testcases.md`，原型图见 `docs/design/mockups/review-0.0.4/`）
> **决策**：D-11 ~ D-13、D-47 ~ D-49 全部拍板，见 §8

## 1. 最终目标

**兑现「记录」这件事的回报：用户能回看一段时间里的积累，而不只是逐条翻时间线。**

写入路径已经很完整（标签、封面、地图、照片、评分、短评），但回读侧几乎只有一条路：

| 现有回看方式 | 阅读单位 | 回答的问题 |
| --- | --- | --- |
| 首页时间线（`selectTimeline`，按 `finish_date` 倒序、前端按月分组） | 一条 | 「最近发生了什么」 |
| **回顾页（本期新增）** | 一年 | 「这一年积累了什么」 |

时间线是**逐条流**，越翻越深；回顾是**聚合面**，一眼看全。差距不在数据——`finish_date`、`rating`、`tags`、地点经纬度、笔记数这些原材料全部已存在——而在没有一个把它们按年收拢的视图。本期零表结构变更，是一个纯聚合的阅读层。

**回看是私人的**：目录（影单 / 书单 / 时间线）对访客公开，回顾页仅登录可见（D-11）。分享出去的是一条条记录，不分享「把记录拼起来的那个人」——年度总数、标签分布、评分 Top 是关于**人**的摘要，而非关于**内容**的目录。访客理论上能从公开时间线逐页拼出同样的数字，所以私有不是保密，而是产品表态：不主动把关于自己的摘要端出去。这与 0.0.3 心愿单私人化（设计结论 108）同一立场——给记录者的回报，不面向访客。

## 2. 范围

新增前台回顾页与后端年度聚合接口。**零表结构变更、零字典变更、零写入路径**，全部基于现有数据（`finish_date`、`rating`、`tags`、`sgj_item_place` 经纬度、笔记数量）聚合。涉及影视 / 书籍 / 足迹三个条目模块与笔记的数量统计，不修改任何模块的现有页面。

### 3.2 需求说明

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-004-1 | 年度回顾页 | 按自然年汇总该年度 `DONE` 条目数量（分类型：电影 / 电视剧 / 书籍 / 地点）与笔记数量。年份可在页内切换，「有数据的年份」从数据推导（`finish_date` / `create_time` 的去重年份），不得硬编码。**归因口径**：条目按 `finish_date` 归因自然年，笔记按 `create_time` 归因自然年（笔记没有「完成」概念，两类记录的时间轴不同，不得混用）；`finish_date` 为空的 `DONE` 条目无法归因，不计入任何年度。页面遵循前台既有的移动端适配标准 |
| FR-004-2 | 足迹地图回顾 | 该年度 `DONE` 的地点在**手绘示意地图**上呈现（D-47 手绘皮肤在本页灰度），**两档密度**：地点数 ≤ 10（移动端视口 ≤ 5）逐点绘制、按 `finish_date` 先后以虚线串联；超过则聚合计数。**聚合粒度自适应**：先按省聚合（境外地点按国家成泡），泡数超过 12 自动降一级按大区（境外并成「境外」泡），图上须标明所用粒度。**精度分工**（D-49）：示意底不承担地理精度（页面明写「手绘示意 · 非比例地图」），精确位置在点开时才交给高德。**弹层两级**：点图钉开「点详情」（封面/照片位 + 地名 + 日期 + 评分 + 短评 + 标签 + 「在地图上定位」「看这条记录」）；点聚合泡开「组地图」（高德瓦片裱手绘边框、该组地点按真实坐标落图钉、点图钉继续下钻到点详情，SDK 首次打开才加载）。无坐标地点（`latitude` / `longitude` 为 null）不上图但须在图内交代，不得静默丢弃或抛错——年度地点数与图钉数可能不一致，属正常。数据源为**新增按年聚合接口**（地点含 `province` / `country` / 坐标 / 评分 / 短评 / 标签 / 封面），不复用 `/app/travel/trajectory`（全量、含 `wish`、无评分短评） |
| FR-004-3 | 评分 Top | 该年度评分最高的 N 部影视 / N 本书，影视与书籍分榜；地点不设 Top 榜（`rating` 虽在 `sgj_item` 主表、地点理论上可评分，但本期范围只做影视 / 书籍两榜）。参与条件：`rating` 非空（`decimal(3,1)`，0-10）——未评分的 `DONE` 条目不参与；同分时的次级排序（建议 `finish_date` 近者在前）与 N 值（建议 5~10）设计定 |
| FR-004-4 | 标签分布 | 该年度 `DONE` 条目的标签分布（影视 + 书籍 + 地点条目；**笔记标签不并入**——笔记只计数量，正文与标签的年度盘点本期不做）。**现状核实**：`tags` 为 `varchar(500)` 英文逗号分隔，聚合需拆分（SQL 拆或 Java 拆，设计定），需处理空串与标签内空格的清洗。展示取 Top-M 加长尾折叠，M 值设计定 |
| FR-004-5 | 入口 | **首页 hero 按钮排加入口卡**（设计图方案 A：与既有「旅行足迹地图」入口卡同形制的 62px 胶囊卡，副标题带最近有数据年份的数字，如「2024 · 87 件小事」；桌面导航保持 6 项不动、移动端 tab 保持 4 项不动）。**入口仅登录态渲染**，访客不出现回顾入口（D-11 已拍板仅登录可见，对齐 0.0.3 心愿条 / 心愿单的处理）；`/review` 不进免登录白名单，访客直达被路由守卫弹去登录 |

## 4. 非目标

- 不做年度报告的图片分享 / 导出（长图、海报）；
- 不做跨年对比、连续记录天数等排行玩法（**D-13 已拍板不做**：与「个人记录」的产品调性不符，断更易产生挫败感）；
- 不做用户自定义时间段回顾（**D-12 已拍板本期仅自然年**，降低范围）；
- 不做笔记内容的年度盘点（笔记仅计数量，不聚合笔记正文、标题、标签）——**已确认顺延到 0.0.5，见 [pending.md](pending.md) D-50**；
- 不新增任何写入路径或数据采集——回顾是纯只读聚合层。

## 5. 验收标准

- [ ] 回顾页按年份正确汇总条目数与笔记数，与首页统计口径一致（`status='DONE'` + `del_flag='0'` + `AppScopeHelper` 范围），全年各类型之和等于年度总数；
- [ ] 条目按 `finish_date` 归年、笔记按 `create_time` 归年，`finish_date` 为空的 `DONE` 条目不计入；跨年条目（创建与完成不同年）归入完成年；
- [ ] 足迹分档正确：地点 ≤ 10（移动端视口 ≤ 5）逐点绘制，否则聚合；聚合先按省、泡数 > 12 自动降到大区；境外地点按国家成泡、大区档并入「境外」；图上标明所用粒度；
- [ ] 无坐标地点不渲染图钉、不抛错，且在图内有文字交代（不得静默丢弃）；
- [ ] 逐点档连线按 `finish_date` 先后、在图钉圆边收住（不穿入圆内）、不与文字标签互相压盖；
- [ ] 点详情弹层字段完整（日期 / 评分 / 短评 / 标签 / 封面或照片位）；组地图弹层内高德瓦片按真实坐标落图钉、点图钉可继续下钻；
- [ ] 高德 SDK 仅在首次打开弹层时加载：回顾页首屏网络请求不包含高德 SDK；
- [ ] 标签分布与条目上实际存储的标签一致（逗号拆分正确，空串与空格清洗无误）；
- [ ] 回顾是私人内容（D-11）：匿名访问回顾页被路由守卫弹去登录、回顾接口返回 401、访客首页不出现回顾入口（对齐 `/plan` 的处理）；
- [ ] 无数据年份有合理空状态，不出现除零或空白页；年份切换与年份列表正确；
- [ ] 回归：首页时间线分页、`/plan` 三态流转、心愿对访客清零等 0.0.3 既有行为无回归（回顾页为纯新增读路径，不应触碰既有查询）。

## 6. 数据与兼容性

- **无表结构变更、无字典变更**；
- **可见性（D-11 已拍板：仅登录可见）**：回顾页对齐 `/plan` 的私人内容处理——路由守卫弹登录、回顾接口**不标 `@Anonymous`**（匿名访问 401）、访客不渲染入口；登录态聚合范围经 `AppScopeHelper.resolveCreateBy()` 解析（其他登录用户 = 自己的数据，博主 / 管理员 = 全量），**不得另写一套过滤**。每个登录用户各自回看自己的年度，笔记数为本人全量（无访客分叉，不涉及 `publicOnly` 口径）；
- **脱敏**：回顾接口仅登录可达，**无访客脱敏需求**；Top 榜等条目返回结构按页面需要定（登录态时间线本就返回 `comment` / `remark` 全量字段）；
- **口径复用**：聚合查询复用 `SgjDashboardMapper` 的既有 `where` 前缀（`del_flag` + `createBy` + `status`），避免为回顾另建一套统计口径导致数字对不上；
- **性能**：年度扫描与 `tags` 拆分在个人数据量级（千级条目）无压力；`finish_date` 无索引、走全表扫描在此量级可接受（设计阶段复核，不预先加索引）。

## 7. 风险与现状核实

| 项 | 现状 | 对本期的影响 |
| --- | --- | --- |
| 轨迹接口不按年过滤 | `/app/travel/trajectory` 返回全量 `visited` / `wish` 图钉 | 已定不复用：新增按年聚合接口返回地点全量字段（FR-004-2），`trajectory` 保持不动 |
| `sgj_item_place` 的 `province` 可能为空 | 境外地点（富士山 / 悉尼歌剧院）与未选省的地点 `province` 为 null | 聚合键须处理：`country` 非「中国」（或非空且 `province` 为空）按国家成泡；两者皆空的归「未分类」，不得 NPE |
| 高德 SDK 体积与首屏代价 | `loadAMap()` 为进程内单例懒加载（`utils/map.ts`） | 组地图弹层首次打开才加载：回顾页首屏零地图依赖；SDK 加载失败须有降级（弹层内以清单兜底，不白屏） |
| `tags` 为逗号分隔文本 | `varchar(500)`，多个英文逗号分隔，存在含空格的脏数据（`test_data.sql` 有 `tags <> replace(tags,' ','')` 的校验行） | 标签分布依赖拆分正确性，须有空串 / 空格清洗（FR-004-4） |
| `finish_date` 可能为空 | `selectTimeline` 按 `finish_date` 排序但不过滤空值 | 年度归因必须显式排除空 `finish_date`，否则出现「总数 ≠ 各年之和」（FR-004-1） |
| 两套统计查询并存 | 首页 `buildSummary` 与回顾聚合是不同查询 | 口径漂移风险：回顾的 `where` 前缀须与 `selectTimeline` / `selectItemTypeStats` 逐字对齐（§6） |

## 8. 决策状态

**已拍板（随详细需求定稿）**

| 决策 | 结论 | 影响 |
