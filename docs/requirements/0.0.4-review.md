> **版本状态**：✅ 已确定
> **表结构变更**：无（全部基于现有数据聚合）
> **设计方案**：尚未产出（开工前需先评审）
> **决策**：D-11 ~ D-13 未拍板，其中 D-11 为范围类，见 [pending.md](pending.md)

## 1. 最终目标

**兑现「记录」这件事的回报：用户能回看一段时间里的积累，而不只是逐条翻时间线。**

## 2. 范围

新增前台回顾页与后端聚合接口。**零表结构变更**，全部基于现有数据（`finish_date`、`rating`、`tags`、地点经纬度、`item_type`、笔记数量）聚合。

## 4. 非目标

- 不做年度报告的图片分享 / 导出（长图、海报）；
- 不做跨年对比、连续记录天数等排行玩法（见 D-13）；
- 不做用户自定义时间段回顾（本期只按自然年，见 D-12）。

## 5. 验收标准

- [ ] 回顾页按年份正确汇总条目数与笔记数，与首页统计口径一致；
- [ ] 地图仅展示该年度 `DONE` 的地点，且不出现无坐标地点导致的渲染异常；
- [ ] 标签分布与条目上实际存储的标签一致；
- [ ] 访客访问时严格遵守可见性边界（见 §6）；
- [ ] 无数据年份有合理空状态，不出现除零或空白页。

## 6. 数据与兼容性

- 无表结构变更。
- 需明确回顾页的可见性：若对访客公开，必须复用 `AppScopeHelper` 的 `publicOwner` + `is_public` 规则，**不得另写一套过滤**，否则会绕过既有的公开数据边界（`AppHomeController` 的脱敏逻辑是同一处约束）。
- 复用现有 `SgjDashboardMapper` 的聚合思路，避免为回顾另建一套统计口径导致数字对不上。
