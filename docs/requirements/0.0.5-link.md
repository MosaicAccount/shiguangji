# 0.0.5 —— 链接

> **版本状态**：✅ 已确定（详细需求已定稿；D-14 ~ D-16、FR-005-5、D-50 已拍板，见 §8）
> **表结构变更**：无（反向链接锁定轻方案，见 §6）
> **设计方案**：尚未产出（开工前需评审 `docs/design/link-architecture.md` / `link-design.md` / `link-testcases.md`）
> **决策**：D-4、D-14 ~ D-16、D-50 与 FR-005-5 已拍板，见 §8

## 1. 最终目标

**让知识之间可以互相走过去，把「笔记列表」变成「知识库」，同时为 AI 接入准备数据基础。**

本版走通两条「走过去」的路，另补一个「找得回」的入口：

| 路径 | 入口 | 回答的问题 |
| --- | --- | --- |
| 写这篇时引用别篇 | 正文里的 `[[标题]]`，详情页可点 | 「这件事我在另一篇里写过」 |
| 读这篇时看谁引用它 | 详情页正文末尾的反向链接区块 | 「我当时从哪篇走过来的」 |
| 忘了在哪写过 | 前台头部搜索入口 + `/search` 聚合页 | 「我记得记过，但忘了记在哪」 |

三条路都不新增存储：互链就是正文里的文本标记，反链从正文派生，搜索复用既有全文索引。**`sgj_note.content` 仍是纯 Markdown**——这是后续 AI 按段落切块向量化的前提，现在遵守零成本。

**链接的地址是标题。** 不引入 `[[#id]]` 写法，是因为人写的时候记得的是标题而不是 ID；代价是改名会断链、重名会有歧义，这两条分别由 FR-005-6 的保存前提醒与 D-14 的降级口径兜住，而不是靠给内容加元数据（那会破坏纯 Markdown 约束）。

## 2. 范围

笔记正文的互链语法与渲染、反向链接区块、失效链接降级、标题变更提醒；新增前台全局搜索入口与跨「条目 + 笔记」的聚合检索页。涉及笔记模块、前台头部与新增搜索页。

**零表结构变更、零字典变更、零写入路径改造**；不新增依赖。

影视横向关联（原 FR-005-4）已拍板移出本版（D-16），笔记年度盘点（D-50）继续顺延。

### 3.3 关键口径

#### 3.3.1 互链语法（FR-005-1）

- 标记形如 `[[标题]]`；括号内首尾空白忽略（`[[ 标题 ]]` 与 `[[标题]]` 等价），其余字符逐字比较，**区分大小写**（库里的标题保存时已 trim）。
- 只在**正文普通文本**里生效。围栏代码块、行内代码、已有 Markdown 链接的文字与 URL、图片 alt、HTML 标签内部一律不解析——这是「代码里的 `[[1,2],[3,4]]` 不能被当成链接」的底线。
- 未闭合的 `[[`、空的 `[[]]`、嵌套括号（如 `[[a [[b]] c]]`）都按普通文本原样显示。
- **已知限制**：标题本身含 `[`、`]` 或换行的笔记无法被此语法引用（标记在语法上不成立），不另设转义。
- 渲染范围只有**前台笔记详情页**（`/note/detail?noteId=`）。编辑页预览、后台笔记管理、Markdown 导出都不解析，token 原样保留（导出仍是纯 Markdown）。
- **列表摘要**：`[[标题]]` 去掉括号、显示为纯文本标题，不可点。列表卡整块已经可点进详情，卡片内再嵌链接既抢点击、又在窄卡片里误导；摘要保持纯文本也避免把 HTML 注入列表。
- 不做别名（`[[标题|文字]]`）、不做 `[[#noteId]]`、不做标签互链。

#### 3.3.2 解析与可见性（FR-005-1 / FR-005-3）

- 解析范围＝**当前查看者可见的笔记**，与笔记详情接口同一口径（匿名＝公开笔记；登录后经 `AppScopeHelper.resolveCreateBy()`），不另写一套过滤。
- 可见范围内命中 1 篇 → 正常链接；命中 0 篇 → 「未找到」降级；命中 ≥2 篇 → 「标题重名」降级（D-14：不确定就不猜，绝不静默跳到错的那篇）。
- 对匿名访客，「私密笔记」与「不存在」都表现为**未找到**，不泄露私密笔记的存在性。
- 渲染所需的目标笔记映射随详情页一次加载下发（是否独立接口由设计定）；**不得为正文里的每条链接单独发起请求**。

#### 3.3.3 反向链接口径（FR-005-2）

- 「引用」的定义：来源笔记正文里出现了指向**本篇标题**的标记，且按 §3.3.1 的口径真的会渲染成链接——**代码块 / 行内代码里的 `[[...]]` 不算引用**，否则反链面板会列出实际点不过去的来源。
- 来源范围：当前查看者可见、`del_flag='0'`、**排除本篇自身**；匿名只统计公开来源。来源不可见时连标题都不出现。
- 标题重名时（本篇标题在可见范围内不唯一），指向它的链接全部降级，反链区块**不列来源、不显示计数**，改为一行说明「本篇标题与另外 N 篇重复，引用无法定位到本篇」。
- 每条来源展示：来源标题（可点）、更新时间、包含该标记的一小段正文（纯文本，标记处高亮）；同一来源出现多次只列一条，可标注处数。
- 排序按来源 `update_time` 倒序；区块标题显示引用篇数。
- 位置：正文末尾 `· 完 ·` 之后，桌面与移动**同一位置**（右侧 aside 继续只承担大纲，不塞第二种内容）。
- 读取方式与详情同一次加载或独立接口由设计定；不新增表、不做缓存（升级路径见 §6）。

#### 3.3.4 降级样式（FR-005-3）

- 视觉上与正常链接可区分（虚线 / 灰底 / 小标记任一，设计定），**不可点**，但保留标题文字。
- 悬停 / 聚焦给出原因：`未找到` 或 `标题重名，无法确定目标`；匿名场景不区分「私密」与「不存在」。
- 不写错误日志、不弹全局提示、不影响同篇其余正文与大纲。

#### 3.3.5 全局搜索（FR-005-5）

- **入口**：前台头部主题切换左侧的搜索图标，桌面与移动都在头部；桌面导航保持 6 项、移动底部 tab 保持 4 项不动。点击进入 `/search`。
- **页面**：顶部关键词输入框（进入自动聚焦），Enter 或按钮提交；`/search?keyword=` 可直链、可刷新、浏览器返回保留关键词。
- **分组**：固定顺序 影单 / 书单 / 足迹 / 笔记；影单内电影与电视剧**混排**（用类型徽标区分），不是各取一半；空组不显示；组头显示该组命中总数。
- **条数**：每组最多 10 条，本期不做搜索结果分页与组内展开（关键词更具体即可收窄）；超出部分不静默丢弃，组头数字如实反映总数。
- **匹配**：条目按 `title like`（不搜标签、短评、备注、导演、演员、作者）；笔记按既有「标题 + 正文」全文检索（ngram，至少 2 字），复用现有 `cleanKeyword` 剔布尔运算符与 like 兜底逻辑。
- **最少字数**：统一 2 字（与笔记页一致，ngram 单字切不出 token）；不足时前端提示、不发起请求。
- **排序**：组内按 `update_time` 倒序（复用既有列表口径）；不做跨类型相关度排序。
- **跳转**：条目 → 所属模块页并带 `?itemId=`（电影 / 电视剧同时带 `?type=`，与首页时间线同一套深链）；笔记 → `/note/detail?noteId=&keyword=`（复用既有关键词高亮与命中计数）。
- **可见性**：复用各模块既有口径——匿名仅 `publicOwner` 的条目与公开笔记；结果**不下发** `comment` / `remark`，因此不需要另做访客脱敏分支。
- **状态**：未输入 → 说明可搜什么；无结果 → 「没有找到，换个关键词试试」；接口失败 → 可重试，不白屏。
- **路由**：`/search` 必须加入 `PUBLIC_ROUTES` 免登录白名单（连同 `publicRoutes.spec.ts` 一起改）——漏加会让匿名访客被守卫弹去登录（0.0.3 `/plan` 踩过的坑）。

#### 3.3.6 标题变更提醒（FR-005-6）

- 保存时比较新旧标题；标题变化且旧标题存在 ≥1 条反链 → 确认框「有 N 篇笔记仍引用旧标题「X」，保存后这些链接会失效」，提供「继续保存」与「返回修改」。
- 不自动改写任何笔记正文，不提供批量替换链接。
- 反链为 0 或标题未变 → 不打断保存。
- 旧标题本身已重名（链接本就降级）时仍提示，不特殊处理。

## 4. 非目标

- 不做别名 / ID 写法 / 跨条目链接 / 标签互链 / 外部资源引用；
- 不做知识图谱可视化、链接关系图、入链出链的图形式浏览；
- 不做重命名时自动回写引用、批量替换链接；
- 不做搜索结果分页、跨类型相关度排序、输入联想 / 即时搜索；
- 不做编辑预览、后台笔记管理、Markdown 导出里的互链解析；
- **影视横向关联本期不做**（D-16 顺延）；
- **笔记年度盘点本期不做**（D-50 继续顺延）；
- 不做 AI 对话、摘要或问答；
- 不新增 `sgj_note_link` 关系表，也不做存量正文回填（D-15 轻方案）。

- [ ] 代码块、行内代码、既有链接文字/URL、图片 alt 里的 `[[...]]` 原样显示、不成链、不产生反链；

- [ ] 匿名查看公开笔记时，指向私密笔记的标记显示「未找到」，响应与页面都不泄露私密笔记存在性；
- [ ] 反链来源准确：代码块里的标记不算、回收站笔记不算、本篇自身不算、查看者不可见的来源不算；计数与列表条数一致，每条都能跳转；
- [ ] 本篇标题重名时，反链区块显示说明而非来源列表；

- [ ] 编辑页改标题保存时，若有引用则弹出确认；选「返回修改」不落库，选「继续保存」正常保存且不自动改任何正文；

- [ ] 回归：Markdown 既有语法（标题、列表、代码块、表格、图片、链接、任务列表）渲染无回归；关键词高亮与大纲正常；笔记导出仍是原文（token 原样）；笔记列表摘要与命中计数不回归；笔记草稿不回归；模块列表检索与 `?itemId=` 深链不回归；`/plan`、`/review` 的私人可见性不回归；

## 6. 数据与兼容性

- **零表结构变更、零字典变更、零索引变更**：无新表、无新列、无迁移脚本；搜索与反链都走既有列（`sgj_note.title` / `content` / `update_time`、`sgj_item.title`）与既有索引（`ft_note_title_content`、`idx_sgj_note_title`、`idx_sgj_item_title`）。
- **`content` 保持纯 Markdown**：互链是正文里的文本标记，不拼结构化元数据；导出 `/app/note/{id}/export` 仍输出原文，token 原样。
- **向后兼容**：`[[...]]` 在存量正文里从未被解释，本版起才解释。存量内容若本就有 `[[...]]`（如引用编号），会开始被解析或降级——属已知行为变更，不做迁移；代码块内的不受影响。
- **口径复用**：笔记侧搜索复用 `SgjNoteServiceImpl.selectSgjNoteFrontList` 的可见性、摘要与全文兜底；条目侧复用 `selectSgjItemList` 的可见性与排序（影单组的电影+电视剧混排需要 `item_type in (...)` 的查询能力，属新增查询而非新口径）；反链与链接解析复用 `AppScopeHelper.resolveCreateBy()`，不另写过滤。
- **反链实现**：先按 `content like '%[[标题]]%'` 取候选（标题里的 `%` / `_` 需转义），再用与渲染一致的口径（剔除代码块）做精确校验，避免误报与漏报。
- **性能**：反链是详情页一次 LIKE 扫描 + 精确校验，个人量级（千篇以内）可接受，不做缓存；条目搜索的 `%关键词%` 不走索引、每组截断 10 条，同样在个人量级内。**升级路径**：笔记量或公开访问量上来后，新增 `sgj_note_link` 与一次性回填，接口形状保持不变。
- **D-15 轻方案的代价已接受**：每次详情都要扫一遍正文；换来零迁移、零回填、零「表与正文不一致」。
- **ngram 限制**：全文索引 `ngram_token_size=2`，单字搜不到；全局搜索统一 2 字门槛，与笔记页一致。

## 7. 风险与现状核实

| 项 | 现状 | 对本期的影响 |
| --- | --- | --- |
| 标题即地址 | `sgj_note.title` 无唯一约束、可随时修改（`varchar(200) not null`，保存只校验非空） | 改名断链、重名无法解析；用 D-14 降级 + FR-005-6 提醒兜住，不引入 ID 写法 |
| 笔记摘要为纯文本 | 后端 `SgjNoteUtils.stripMarkdown` 产出摘要，列表卡整块可点 | §5 草案的「列表预览可点」改为「摘要去括号显示为纯文本」，否则要在窄卡片里注入可点 HTML 并与整卡点击打架（§9 记录） |
| 全文索引已存在 | `ft_note_title_content (title, content) with parser ngram`；笔记页已有标题+正文检索与 0 命中 like 兜底 | 笔记侧搜索零新增；单字限制沿用到全局搜索 |
| 条目检索只有标题 | `selectSgjItemList` 有 `title like`，无导演 / 演员 / 作者检索 | 全局搜索的条目组只搜标题；「按导演 / 演员找人」属于已移出的 FR-005-4 |
| 条目详情是抽屉 + `?itemId=` 深链 | 影 / 书 / 足迹都有 `openDetailById` 与 query 处理（电影还有 `type` / `status`） | 搜索结果可直达详情，不需要为搜索新开详情页 |
| 前台头部无搜索入口 | 主题切换旁没有搜索元素；`HeaderSearch` 被后台侧栏引用，是菜单搜索、零后端调用 | 新增图标入口，不动导航项数量；不复用 `HeaderSearch` |
| 模块列表页不从 URL 读关键词 | note / movie / book / travel 的 `keyword` / `title` 只存在输入框里 | 本期搜索页不做跨页「查看更多」跳转，避免改四个页面的 URL 口径（§4 非目标） |
| `/search` 需免登录 | `PUBLIC_ROUTES` 白名单 + `publicRoutes.spec.ts` 单测 | 漏加会让匿名访客被弹去登录（0.0.3 `/plan` 的旧坑），必须连同单测一起改 |
| 反链是正文扫描 | `content` 为 longtext，无专门索引；LIKE 前置通配不走索引 | 个人量级可接受；标题含 `%` / `_` 时 LIKE 需转义，精确校验兜底；升级路径见 §6 |
| 既有正文可能含 `[[...]]` | 测试数据中未出现；代码块内的不受影响 | 解析上线后普通文本里的 `[[x]]` 会变成链接或降级，属可接受的已知变更，不迁移 |
