## 3. 背景与现状

### 3.1 产品定位

拾光记用于记录电影、电视剧、书籍、旅行地点和笔记。前台是匿名可浏览的「一人公开博客」（仅 `publicOwner` 账号的公开数据），后台登录用户按账号隔离管理自己的数据。

### 3.2 现状盘点

四个内容模块（影单 / 书单 / 足迹 / 笔记）共用同一套工作流，而不是四套：

| 模块 | 前台页面 | 状态枚举 | 状态字典 |
| --- | --- | --- | --- |
| 电影、电视剧 | `/movie`（顶部 tab 切换类型） | `WANT` / `DONE` | `sgj_movie_status` |
| 书籍 | `/book` | `WANT` / `DONE` | `sgj_book_status` |
| 旅行地点 | `/travel`（含足迹地图、照片） | `WANT` / `DONE` | `sgj_place_status` |
| 笔记 | `/note`（含列表 / 详情 / 编辑） | 无状态 | — |

三个模块的条目操作完全同构：**添加想看 → 标记看过（填日期 / 评分 / 短评）→ 出现在首页时间线**，另有「取消看过」反向操作。

已具备的能力：统一标签体系（五模块，仅可选择不可手输）、封面与照片、地图选点、Markdown 笔记、笔记大纲导航、软删除回收站、前台主题切换与移动端适配。

### 3.3 三个结构性缺口

现状的问题不在「某个模块缺功能」，而在三条穿过所有模块的线没有走通：

1. **时间轴断了中间一节。** `sgj_item.status` 只有 `WANT` 和 `DONE`，没有「进行中」。核心闭环 `想 → 做 → 记` 里，「做」这一段不存在——想看的剧某天直接变成看过。而 `sgj_item.start_date` 字段建表时注释即为「开始日期（观看/阅读/**计划时间**）」，前台四个页面均未使用。
2. **回看路径只有一条时间线。** 写入路径已很完整（标签、封面、地图、照片、评分、短评），但唯一能「回看」的地方是首页按月分组的时间线。记录类产品的回报在回看，这一侧几乎是空的。
3. **知识之间没有连接，内容不可检索。** 笔记正文搜不到（`SgjNoteMapper.selectSgjNoteList` 仅有 `title like`），笔记之间除可挂一个条目外无任何互链，条目之间也无关联（有导演/主演字段却无「同导演的其他片」）。前台没有全局搜索；`HeaderSearch` 被后台侧栏引用（`layout/components/Sidebar/index.vue:39`），且是 Fuse.js 的**菜单**搜索、零后端调用——所以前台要做内容搜索需重写该组件并新增聚合接口，而非「接上既有组件」（见 0.0.5 的 FR-005-5）。

- **笔记导入 / 导出** —— Issue #14 由他人负责，待其合入后再评估是否需要补漏；

## 5. 跨版本约束与原则

1. **概念控制原则。** 判断一个需求该不该做，看它让「记录」的边界变宽了，还是只让产品里的概念变多了。变宽是收益，变多是债。据此：标签已覆盖场景不加分类 / 文件夹；不加「想法」等新的记录类型（一条想法即一条无标题的短笔记，无需新表）；轻量入口优先于新模块。
2. **最小改动优先。** 优先复用既有表和字段——`sgj_item.start_date` 即为先例（字段早已存在，只是前台未用），而不是新增字段。
3. **数据边界不可绕过。** 所有前台读接口必须经 `AppScopeHelper` 过滤；匿名访客仅可见 `publicOwner` 的公开数据，笔记受 `is_public` 约束。新增的读接口（回顾页、全局搜索、计划视图）一律复用该约束，不得另写过滤逻辑。
4. **`content` 保持纯 Markdown。** 不把结构化元数据拼入正文。
5. **新增依赖须说明理由。** 无标准库或既有依赖可替代时才引入（0.0.2 的语法高亮库属此列）。
6. **每期须有回归清单。** 触及共享代码（状态模型、`SgjDashboardMapper`、`AppScopeHelper`）时，必须回归既有流程，不接受存量功能回归。

## 6. 开发与提交约定

- 每个版本从 `develop` 拉出特性分支，完成后合回 `develop`（参照标签管理的分支流程）；
- **开工前置条件**：该项状态须为 ✅ 已确定（已批准立项），且该版本的范围类决策已拍板；
- 每个版本先产出该版本的**详细需求**与**设计方案**（需求写在本文档夹的版本文件里，设计成文于 `docs/design/<主题>-design.md`，可参照 [note-0.0.2-design.md](../design/note-0.0.2-design.md)），评审通过后再进入编码；
- 每个完成的功能点独立提交，前缀 `feat:` / `fix:` / `docs:`，涉及 Issue 时在提交信息中带上编号；
- 提交前运行受影响应用的检查：前端 `npx vue-tsc --noEmit` 与 `npm run build:prod`，后端 `mvn -pl shiguangji-admin -am test`；
- 触及「跨版本约束与原则」第 6 条所列共享代码时，在 PR 描述中列出回归验证过的存量流程；
- 状态变更（如某 🔵 项拍板为实施、某 ⚪ 项拍板为不做）须同步更新本文档的版本总览表，以及 [pending.md](pending.md)，保持需求文档为唯一事实来源。
