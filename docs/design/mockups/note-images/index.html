带图笔记的图片搬运

承接 FR-002-8 导入链路的边界 3：带图 md 导入后图片引用会整片失效。本组图把「用户自己指出图在哪」这条补回来的路上，两个新界面画出来。

怎么用

  • 每屏一页，页内用顶部工具条切换：状态、深色模式、桌面 / 移动端、标注。
  • 橙色数字气泡与页脚「本屏标注」一一对应；关掉「标注」是无打扰观感。
  • 设备框是可滚动的真视口：弹窗里的文件清单、编辑器的分屏预览都能滚，可以据此判断遮挡与留白。
  • 视觉基线取自 shiguangji-web/src/assets/styles/front-tokens.scss（冷雾胶片 v3.3）；弹窗与编辑器沿用 Element Plus 结构，但配色走 --sgj-*（前台主题下的 Element Plus）。

本组图是静态保真，不连接真实接口：按钮可点、弹窗可关、状态可切，但文件选择器、上传与插入均为示意。这些是刻意的边界，不是缺失。

出图口径

  • 覆盖：FR-002-8 边界 3 的「图片引用无法转存」所说的两条出路——导入时搬运（屏 1）与导入后手工补图（屏 2）。0.0.2 已发布的导入拦截框、超长拦截框、草稿冲突框均不变，不重复出图。
  • 每屏都有移动端（≤768px）与深色模式两个变体——页内切换，不另存文件。屏 1 的移动端差异是弹窗近满宽、按钮竖排；屏 2 的移动端差异是编辑器单栏 + 顶部「预览」按钮。
  • 文案即定稿：两屏里的中文文案按 [设计定稿] 逐字使用，会与实现逐字对齐；图里的说明性文字只出现在标注与页脚，不混进界面文案。
  • 图片占位：全部用 CSS / SVG 画的灰色圆角块（带「图」字），不引用任何外部图片；插入成功后正文里的 /profile/upload/… 与预览里的 /dev-api/profile/upload/… 都是真实行为（photoUrl() 给站内相对路径补 VITE_APP_BASE_API 前缀）。
  • 本组图不含：搬运的后端接口与存储形态、图片去重与孤儿文件对账、data: base64 内嵌图（明确不处理）、docx 里的内嵌图片（转后续版本）、条目标题里的图片与相册（走既有上传）。
