本屏标注

  1. 新增：MarkdownEditor 工具栏左端新增「插图」按钮——这是 0.0.2 设计结论 35 里「笔记编辑器根本没有插图入口」的那条缺口的补法。按钮在右侧预览之前、文字提示的左侧，与既有「支持 Markdown 语法…N 字」各自成组，不挤掉字数统计。
    位置选在一行两端的左端、而不是塞进右侧：右侧已被预览按钮（移动端）与字数占满，再加一个按钮会让移动端工具栏换行。
  2. 新增：按钮下方一行小字说明插入位置与粘贴入口。两件事都要说：光标不在末尾时用户不知道插到哪，而粘贴截图是拿到截图后最自然的那条路（比先存盘再选文件快）。小字常驻，不是 hover 提示——hover 提示在触屏上等于不存在。
  3. 新增：上传中按钮转 loading 并禁止重复点，正文与右侧预览都不动。上传是异步的，光标位置会随用户继续打字漂移——实现按「点击那一刻记录的光标位置」插入，而不是完成时刻的；否则用户等上传时随手打两个字，图片就插到了句子里。
  4. 新增：插入成功后正文出现 ![](/profile/upload/2026/10/10/9f3c1a….png)，右侧预览同步出现图片。这里有个真实行为要留神：预览里的 src 带 /dev-api 前缀——photoUrl() 给站内相对路径补 VITE_APP_BASE_API，所以正文里存的是 /profile/…，预览请求的是 /dev-api/profile/…。生产环境下前缀换成真实网关前缀，存进正文的永远是 /profile/…。
  5. 新增：粘贴截图。剪贴板里有图片时拦截粘贴、自动上传并插入；纯文本粘贴必须先原样放行——拦截时只看 clipboardData.items 里有没有 image/*，不看 text/plain 在不在，两者可以同时存在（从浏览器复制带图内容时就是如此），优先级给图片、同时把文本也照常插入到别处即可，但绝不能因为「带图」就把整段文本粘贴吞掉。
  6. 新增：失败不动正文。格式不支持 / 超限 / 网络错误都在编辑器上方给一条红字（Element Plus message · error 观感），正文与预览保持原样——否则用户无法判断「图片到底进去没有」，而失败的占位语法会留在正文里污染内容。
  7. 既有：移动端隐藏右侧预览、收进顶部「预览」按钮的弹窗（useMediaQuery('(max-width: 768px)') + el-dialog width="94%"），编辑器高度固定 55vh。本屏不改这条，只把「插图」放进工具栏左端——移动端单栏下它同样可用，选文件走系统选择器，截图走输入法粘贴。

未建模：真实上传接口与进度、光标的精确插入实现、多图连续插入、拖拽图片到编辑器的落点（本版不做）、图片删除与回收（正文里删掉 ![]() 不等于删文件）。
既有不改：分屏预览结构、字数统计口径（innerValue.length，含 Markdown 标记）、草稿自动保存与同步三态状态条、离开确认。本屏左上角的「← / 取消 / 保存」与标题栏是既有样式，未改动；为聚焦工具栏，本屏省略了状态条（见 0.0.2 编辑页设计图）。
