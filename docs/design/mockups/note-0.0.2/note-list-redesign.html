本稿的改动

  1. 重设计：卡片布局 4 档可切换——限宽网格（默认）/ 瀑布流 / 单栏阅读 / 全宽（现状）。要拍的就是「卡片多宽、怎么排」。
  2. 操作区合并：导入 md 与 ＋ 写笔记 收进 banner 右上角一组（次级 ghost + 主按钮），筛选栏只留搜索。两个都是「创建」类动作，分居两处等于让人找两遍。
  3. 修正（上一稿的错）：网格里我写了 align-items:start，同行卡片各按内容高度排、底边参差——「高低不同」就是这么来的。已去掉（默认拉伸等高），并把 meta 行贴到卡片底部，同行的「独立笔记 / 标签 / 时间」落在一条基线上。
  4. 我建议网格而不是瀑布流：这一屏干的是「按更新时间扫 + 搜索筛选」，扫描吃横向对齐；瀑布流拿参差的底边换密度，和这种读法冲突。而且 CSS 多栏的阅读顺序是先竖后横——按时间倒序时「同一横排」不再是相邻时间。要用瀑布流得引 JS 瀑布（按最短列定位）把顺序摆正，多一个依赖。
  5. 瀑布流模式下摘要放开截断，卡片高度自然、单卡最窄、密度最高。
  6. 沿用上一稿：摘要纯文本 + 最多 2 行（超出由浏览器在行尾补省略号，不拼字符、不渐隐）；命中次数移进 meta 行右侧（琥珀色小字）；标题 17px / 600。

本稿的已知依赖：摘要里不再出现 ![...](...) 这类半截 Markdown，前提是后端把剥离顺序改成「先剥 Markdown 再截窗」（现状是先截窗后剥，切在语法中间就剥不掉）。本稿按修好之后的样子建模。
