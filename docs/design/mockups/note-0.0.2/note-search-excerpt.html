「一个笔记命中多个关键词，循环播放，怎么播放？」issue #31 评审追问

  1. 结论：不播。一张卡一段摘要——以第一个命中为中心、窗口内的命中全部高亮（多关键词同一样式）；其余命中用「共 N 处命中」小字提示，看全部进详情页（大纲导航已上线）。多词检索是 OR 语义：多个关键词命中时，同一窗口内出现的词都高亮，不在同一窗口的位置由计数兜底。
  2. 多命中自动轮播已评审不采用：文字的阅读节奏（60 字摘要约 3–5 秒）正卡在轮播间隔上，读者被迫和计时器抢内容；动的卡片还会抢走旁边静止卡片的注意力。完整规格与理由在存档图「命中轮播」，留档备查。

决策记录 · 轮播不采用

  • 60 字摘要要读 3–5 秒，正卡在常见轮播间隔上——读者被迫和计时器抢内容。
  • 动的卡片天然抢注意力，干扰旁边静止卡片的阅读；列表页是「读」的场景，不是「看」的场景。
  • 需求低频：第一处命中通常足够判断去留；遍历全部命中是详情页的活（大纲导航已上线）。

已评审不采用：完整轮播规格在存档图 命中轮播，留档备查。

摘要两步速查（后端一处生成）

第一步 · 剥离（Markdown → 纯文本）
代码块整块去掉；图片去掉；链接只留文字；标题、引用、列表去前缀；front-matter 整块去掉；加粗、删除线去标记；HTML 标签去掉；连续空白折叠。
第二步 · 截窗
无关键词：取开头约 120 字。有关键词：以第一个命中为中心，前后各约 40 字，两端省略号。剥完为空（整篇代码块）：回退原文开头。正文为空：摘要为空。

列表不再传整篇正文；命中计数可由同一趟 locate 循环顺带数出，不额外查库。后台列表与 CSV / JSON 导出仍带完整正文，本版不动。

本屏标注

  1. 摘要常显：纯文本、由后端生成；列表不再传整篇正文，卡片不再渲染 Markdown。
  2. 命中窗口：以第一个命中为中心，前后各约 40 字，两端省略号；定位在剥离后的纯文本上做，大小写不敏感。
  3. 高亮：窗口内每次出现都高亮；多关键词同一样式（分色是噪音且色弱不友好）；按字面量 indexOf 切分——关键词含 ( [ * 也不报错，不拼正则、不走 v-html（往返一致性卡：草稿、摘要两词同窗高亮）。
  4. 共 N 处命中——本设计相对 issue 正文的唯一增量：提示其余命中的存在，多于一处才显示；看全部进详情页（大纲导航 #25/#26 已上线）。
  5. 只命中标题：摘要取正文开头，标题本身高亮（边角情况备忘卡；仅 1 处命中，无计数小字）。
  6. 整篇只有代码块：剥离后为空，回退原文开头，不出空白卡片（sed 备忘卡）。
  7. 摘要不与标题重复：正文以同名一级标题开头时，该行在后端已去掉（周复盘的做法卡）。
  8. 渐隐仅在溢出时：摘要定长，桌面通常不溢出；切到移动端可见渐隐生效（MySQL 卡）。

检索语义：多词是 OR（布尔模式，运算符字符已被后端剔除）；至少输入 2 个字才触发。
不动的部分：后台列表与 CSV / JSON 导出仍带完整正文；回收站不纳入正文检索。
已评审不采用：多命中自动轮播（存档见「命中轮播」图）——文字阅读节奏与自动播放冲突，其余命中由「共 N 处命中」+ 详情页承接。
