    删除这份草稿？

    删除后无法恢复——草稿不进回收站，也不会留下副本。

    本屏标注

    1. 新增页：/note/draft，仅登录可进。访客不会出现在这一屏——路由守卫直接跳登录页，所以这里没有访客态；入口只有笔记列表页的草稿入口条，前台导航不加项。这一屏放全部草稿——空白草稿与编辑已有笔记的未保存改动都在里面：空白草稿每人一份（`note_id = 0`，写完保存才会再有新的一份），编辑态每篇笔记一份；「继续写」按身份跳：编辑态回那篇编辑页（带「已恢复未保存的草稿」提示条），新建态按 draftId 继续写。
    2. 新增：标题为空时用正文首行兜底（第 2 条草稿）。取的是与列表摘要同一套剥离逻辑（去 Markdown 标记、去图片、去 front-matter），后端直接给 excerpt，前端不另写一份；最多两行，超出裁掉。
    3. 新增：条目查不到就显示 #id（第 3 条草稿的 🔗 #12，条目已被删）。与笔记列表的做法一致，不做特殊提示。
    4. 新增：相对时间（「3 分钟前」）走 formatTime()，但后端给的是 yyyy-MM-dd HH:mm:ss，必须先经解析函数转 epoch——直接喂进去会渲染成 NaN月NaN日（Safari 上 new Date(str) 直接是 Invalid Date）。
    5. 新增：硬删除 + 确认弹窗。草稿不进回收站，避免出现第二个暂存区；所以这里必须拦一道（不可逆操作才值得确认）。弹窗写明删的是哪一份，焦点移入弹窗、关闭后回到触发它的那个「删除」按钮。
    6. 新增：不做数量上限，也没有配额行——空白草稿每人一份、编辑态每篇一份（行数天然有界：我的笔记数 + 1），出口只有「手动删」「保存成功后删」「笔记被删时一并删」。列表为空时给出去写一篇的出口。
    7. 补齐：加载中与加载失败两个状态（原来只有 4 个状态）。加载用骨架屏并带 aria-busy；失败给「重新加载」，文案说清是网络/服务的问题，并提供另一条出路。
    8. 修正：元信息文字从 --sgj-text-4 换成 --sgj-text-2。原来时间与条目名用的 --sgj-text-4（#A4ADA9）在卡片上只有 2.2:1 对比度，12px 文字远低于 4.5:1 的门槛，等于读不出来；换成 --sgj-text-2 后是亮色 6.8:1 / 暗色 9.6:1。这个 token 在其它几屏也有同样问题，建议单独做一次全组校准，本屏先不扩散。
    9. 修正：移动端触控目标。每行的「继续写 / 删除」在移动端补到 44px 高，主操作「继续写」占满剩余宽度；底部自留 76px 并带上 env(safe-area-inset-bottom)，不被固定标签栏或 home indicator 遮住。
    10. 修正：可访问性。重复出现的「继续写 / 删除」按钮带上了具体草稿名的 aria-label（否则读屏听到的是一串相同的「删除」）；工具条与页面内所有可聚焦元素补了统一的 :focus-visible 焦点环；装饰性的标注气泡标了 aria-hidden；删除结果通过 role="status" 播报。

    本屏不显示：编辑态草稿（改了已发布笔记但没保存的改动）。
    未建模：删除请求失败的收尾（成功路径是即时更新，删除失败沿用「加载失败」那一套口径）；「继续写」之后的跳转与恢复见编辑页。
