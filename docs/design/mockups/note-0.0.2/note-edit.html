离开编辑？

这篇笔记有未保存的改动。你的修改已保存到草稿箱，离开不会丢失；下次进入这篇笔记时会自动恢复。

本屏标注

  1. 新增：同步状态条三态——「已同步到草稿箱」/「仅本地待同步」/「同步失败」。它是本版唯一能让人确认「写的东西已经出去了」的地方，所以状态要具体、不要只说「已保存」。
  2. 新增：已恢复未保存的草稿 状态条。仅在编辑已有笔记、且服务端草稿比已发布内容新时出现。必须可见——否则用户会把草稿内容误认为已发布的正式内容。「放弃草稿」= 删服务端草稿 + 清本地缓冲 + 表单回滚到服务器快照 + 脏标记归位。
  3. 改动：后台自动同步（每 15s、页面隐藏、网络恢复）不发全局错误提示——否则断网时每 15 秒弹一个红字。同时带 repeatSubmit: false，避免被 1 秒防重拦掉。上报失败时状态条转「仅本地待同步」，不打断输入。
  4. 改动：本地缓冲的 key 带用户身份（sgj:note:buf:{username}:{editorKey}）。原来的 key 在新增态恒为 new，同一浏览器换人登录会继承上一个人的未保存内容。
  5. 新增：离开确认弹窗。判据是「与打开时的服务器快照不同」——不能用「与草稿是否相同」，草稿总是最新的，那样写等于永不拦截。文案说明内容已存入草稿箱，而不是「修改将丢失」。
    关闭标签页时浏览器只给通用文案（beforeunload 不可自定义），文案要求只适用于这个弹窗。
  6. 新增：导入预填。标题按 front-matter → 首个 H1 → 文件名取值；front-matter 里的标签归一化后原样预填（表内表外一视同仁，最多 20 个），不写入标签表（结论 38）。超过 10 万字的文件在导入时就拦下、不进本页（结论 34）。
  7. 改动：移动端隐藏右侧预览、收进「预览」弹窗（既有行为），编辑器高度固定 55vh。

未建模：真实保存请求、字数统计逻辑、标签选择器与条目选择器的弹窗、Markdown 工具栏。
本屏不新增：编辑器本身的结构、分屏预览、字符计数都是既有实现；本次只在它上方加了状态条。
