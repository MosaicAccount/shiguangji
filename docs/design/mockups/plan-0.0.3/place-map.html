笔记

本屏标注

  1. 核实：这一屏不是新功能，是现状核实页。需求 FR-003-6 写的是「地图上『想去』与『去过』用不同图钉样式同时展示，不再依赖状态筛选切换」——查代码：TravelMap 同时接收 visited 与 wish 两个数组，各自标 status: 'DONE' | 'WANT'，图钉样式 .tm-pin.visited（鼠尾草 --sgj-moss）与 .tm-pin.want（灰铜 --sgj-amber）是两套，图例也已有三枚。结论：该需求在 0.0.3 之前就已满足，本期无代码改动（D-9 的结论是「纳入本期范围」，纳入的是回归依据，不是改动）。
  2. 新增：两态同屏——左下图例三枚（去过 / 想去 / 照片聚合），画布上两种图钉同时存在，没有任何筛选控件参与。这一屏存在的意义是把它固定成回归基线：日后若有人把图钉合并成一种、或让「想去」依赖筛选才出现，对照本屏即可判定为回归。
  3. 新增：弹卡内的标注同样分两态。点聚合点后每条地点带 去过 / 想去 标签（.tm-pop-tag.done / .tm-pop-tag.want），且「想去但没照片」的条目会显示「暂无」而不是空白缩略图。弹卡是本屏唯一展示「两态在同一个地点分组里共存」的地方。
  4. 新增：聚合点的两态也分得开（见「聚合态」）。聚合牌优先用照片扇形牌，没有照片时退回数字圆片，圆片颜色按簇内是否存在「去过」着色（cluster.points.some(p => p.status === 'DONE')）。所以「想去」为主的城市簇不会显示成绿色——这条容易被误读成「聚合后状态丢失」，图上明确画出来。
  5. 新增：聚合粒度是缩放驱动的：≤6 按省（境外回退国家）、6~9.5 按市、9.5~11.5 邻域（约 8km）、更高逐点。

未建模：真实高德底图与瓦片（图上浅灰网格、水域与道路色块均为 CSS 示意，不加载任何外部资源）、缩放与拖拽交互、聚合牌点击后的视野自适应、照片相册弹窗、地图选点。
本期不改：TravelMap 组件本体、/travel 的地图 / 卡片模式切换、banner 统计、地图下方旅行时间线。本屏与 三态流转屏 的足迹部分是两个不同页面：那边是卡片模式的胶囊与计划日期，这边是地图模式的两态图钉。
移动端差异：地图高度由 540px 降为 420px（既有断点），弹卡宽度收窄到容器内，页头 banner 变纵向，见工具条「移动端」。
