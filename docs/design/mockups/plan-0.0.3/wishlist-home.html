本屏标注

  1. 改动：hero 的统计口径不动——四个数字仍然是「已完成」（看过 / 读过 / 去过 / 写过），DOING 不进这四个格子。理由：这四个格子说的是「已经留下了什么」，而「在看」还没有结果。但心愿条要改：原来它写死的 wish-bar-label 是「心愿 · 想去 / 想读」，且数字来自 buildSummary 的 else 兜底分支——新增 DOING 后，进行中的条目会被静默算进这个数（需求 §7 第 3 行），所以数字与文案必须一起改成显式的三态口径。
  2. 修复：心愿条右侧链接由 /note 改为 /plan。现有代码里这条「全部计划 →」（原为「待完成 →」）指向笔记列表，是错的落点：点进去看到的是笔记，不是自己的计划。本期把它指向新页 /plan。图上按修复后的形态画。这是本组图唯一一条「现状是错的」。
  3. 新增：心愿单列表纳入「在看」条目（原来只含 WANT）。列表排序仍是既有的 create_time desc（最新添加者在前）——本期不改排序，只改集合；排序要按计划日期是 /plan 的事（见 计划页）。每条右侧保留既有的「完成 →」。
  4. 新增：每条显示状态文案（想看 / 在看 / 想读 / 在读 / 想去），用与列表页同族的胶囊，颜色同一套：想*=灰铜、在*=灰陶、去/读/看过的完成态=鼠尾草。没有这行，纳入「在看」之后用户分不清哪条是在进行中的。
  5. 新增：统一完成弹窗的第一个形态：影视（看完日期 / 评分 / 短评），字段与 /movie 既有的「标记看过」弹窗一致。这个组件供四处复用：/movie、/book、/travel、以及首页心愿单的「完成 →」——第四处是本期新接的。
  6. 新增：弹窗打开时日期默认今天，但可改——这是 FR-003-7 的核心。此前首页的「完成 →」是静默写当天（handleComplete 用 new Date() 现算，连弹窗都没有），而列表页的「标记看过」允许选日期：同一个动作两个入口，精度不一致。补记场景（昨天看的、上周末去的）在首页那条路上必然记错日期。做法不是「事后可修正」而是「当时可指定」——后者少一次往返。
  7. 新增：第二个形态：书籍（读完日期 / 评分 / 读后感）。三形态共用弹窗本体，差异只由类型参数决定标签文案与字段集，不复制三份弹窗实现。
  8. 新增：第三个形态：地点（去过日期 / 回忆，无评分）。地点没有「几分」这种评价维度，少一行是刻意的，实现时用字段集参数控制，不要为了「三处一致」硬加一个评分。三处入口的按钮文案也随类型：首页是「完成 →」，模块页是「标记看过 / 标记已读 / 标记去过」。

未建模：真实评分组件（本屏用字符星示意）、日期选择器的弹出面板（只画收起态）、弹窗提交后的 toast 与列表刷新、取消完成 的确认框、首页时间线的分页加载更多（只画了到底提示）。
既有不改：hero 的文字与动效错峰（--d 阶梯）、地图入口卡、分段标题与胶片齿孔、时间线的日期分栏与轨道圆点、最近笔记卡片。移动端差异：hero 变冷炭灰横幅且隐藏统计矩阵与心愿条（既有行为，所以移动端看不到心愿单——这是现状，本屏不动它；心愿条在移动端不可达的问题另议）。
