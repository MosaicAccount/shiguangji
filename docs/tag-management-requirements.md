# 标签管理 - 需求文档

> 关联 Issue：影视、书籍、旅行、笔记都需要标签，但是现在是通过手输的方式，非常繁琐，并且不方便管理。
> 开发分支：`feature/add-tag-management`（从 develop 拉出，完成后合回 develop）

## 1. 背景与问题

系统四大业务模块（影视、书籍、旅行、笔记）均支持标签，但目前标签为**纯手输、英文逗号分隔**：

- 输入繁琐，同一含义的标签容易拼出多个变体（如「科幻 / sci-fi / 科幻片」），无法沉淀为可复用的标签体系；
- 标签没有统一的管理入口，无法查看某模块下已有哪些标签、各标签被使用了多少次；
- 按标签筛选记录依赖 LIKE 模糊匹配，存在子串误匹配（如输入「科幻」会命中「硬科幻」）。

## 2. 目标

1. 建立后台统一的标签管理能力，标签按业务模块归属和隔离；
2. 用户端添加/编辑记录时从预置标签中选择，禁止自由手输；
3. 用户端和后台均可按标签精确筛选记录。

## 3. 范围

**模块**：影视（MOVIE）、电视剧（TV）、书籍（BOOK）、旅行地点（PLACE）、笔记（NOTE）。标签按这 5 个模块分别管理。

**涉及端**：

- 后台管理端：新增「标签管理」页面（CRUD + 按模块筛选）；
- 用户前台：影视/书籍/旅行的编辑弹窗与新增表单、笔记的新增/编辑表单，标签输入改为选择；前台记录列表支持按标签筛选；
- 后台业务管理页（ItemManager、笔记管理）：标签筛选改为选择式，标签展示保持不变。

## 4. 功能需求

### 4.1 后台标签管理（对应验收项 1、2）

| 编号 | 需求 |
|---|---|
| FR-1 | 后台新增「标签管理」菜单页，支持标签的新增、修改、删除、查询 |
| FR-2 | 标签包含：名称、所属模块（MOVIE/TV/BOOK/PLACE/NOTE）、排序、状态（启用/停用）、备注 |
| FR-3 | 支持按模块筛选标签列表，支持按名称模糊搜索 |
| FR-4 | 同一模块内标签名称唯一；不同模块允许同名（如「科幻」只属于影视模块，笔记模块的「科幻」互相独立） |
| FR-5 | 删除标签仅删除标签定义，已使用该标签的记录不受影响（记录上保留原文字） |
| FR-6 | 停用标签：用户端选择列表中不再出现，但已引用该标签的记录展示与筛选不受影响 |

### 4.2 用户端选择标签（对应验收项 3）

| 编号 | 需求 |
|---|---|
| FR-7 | 用户添加/编辑记录时，标签字段为**多选下拉**，选项来源为该模块下状态为启用的标签，**不提供自由输入** |
| FR-8 | 影视、书籍、旅行的新增表单补齐标签字段（当前仅编辑弹窗可填标签） |
| FR-9 | 保存时将所选标签名以英文逗号拼接存入记录（保持现有存储格式，多条记录可复用同一标签） |

### 4.3 按标签筛选记录（对应验收项 4）

| 编号 | 需求 |
|---|---|
| FR-10 | 用户端影视/书籍/旅行/笔记列表支持按标签筛选，筛选值来自该模块标签列表（选择式，非手输） |
| FR-11 | 筛选为精确匹配（一个标签项完整匹配，不做子串匹配） |
| FR-12 | 后台业务管理页同步支持按标签选择式筛选 |

## 5. 非目标（本期不做）

- 不做标签合并、批量重命名后同步更新历史记录（删除/重命名标签后历史记录保留旧文字，属已知边界，见 FR-5）；
- 不做标签层级（父子标签）、标签颜色/图标、标签使用次数统计展示；
- 不改变现有记录的存储结构（标签仍以逗号分隔文本随记录存储，不引入记录-标签关联表）；
- 不做前台标签云/热门标签推荐。

## 6. 验收标准（对照 Issue）

- [ ] 后台管理添加标签管理：`sys_menu` 注册「标签管理」菜单，页面支持 CRUD，权限串 `sgj:tag:*` 生效；
- [ ] 可以根据不同模块进行筛选：标签管理页按 MOVIE/TV/BOOK/PLACE/NOTE 筛选；同模块重名被拦截；
- [ ] 用户添加记录可以选择标签（禁止手输）：五个模块的新增/编辑入口均为多选下拉且不可自由创建；影视/书籍/旅行新增表单可填标签；
- [ ] 可以根据标签筛选记录：用户端四类记录列表与后台管理页均可选择标签精确筛选。

## 7. 数据与兼容性约束

- 存量数据：现有记录 `tags` 列中的逗号分隔文本需做一次性迁移，拆分去重后写入标签表（按记录所属模块归属）；
- 现有接口 `tags` 字段格式（逗号分隔字符串）保持不变，前端展示与导出无需改动；
- 存量记录中可能存在「脏标签」（拼写变体、无归属），迁移后仍完整保留在记录上，可在后台标签管理中逐步补齐规范标签。
